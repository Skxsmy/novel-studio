# NS-409.2 English UI Baseline

Status: advanced redo draft, not user-accepted  
Date: 2026-06-23

This is the NS-409.2 static design baseline for the Novel Studio English UI. It does not change `apps/web/src`, and it does not authorize NS-409.3 implementation before the direction is accepted.

## Scope

The baseline covers the durable authoring shell:

- Library selection
- Overview
- Plan
- Write
- Codex
- Workshop
- Review Inbox
- Settings

Call History and Recovery remain contextual states, not primary navigation entries.

## Redo Context

The previous preview was rejected. The main failures were:

- The far-left single-letter rail had no clear user meaning.
- The project sidebar mixed unrelated object types: workspace navigation, chapter scenes, context basket items, and recent focus rows.
- The writing workspace was not dominant enough for an authoring product.
- The layout behaved like an enlarged desktop mockup instead of a dense, usable wide-screen workbench.

This revision keeps the product in NS-409.2 and rebuilds the static baseline around a cleaner information architecture.

## External References Reviewed

The redesign uses patterns from modern source-backed UI references, adapted to Novel Studio instead of copied directly:

- [Novel editor app source](https://github.com/steven-tey/novel/blob/main/apps/web/app/page.tsx): writing/editor surface first, assistant controls secondary.
- [Outline sidebar header source](https://github.com/outline/outline/blob/main/app/components/Sidebar/components/Header.tsx): sidebar sections should be collapsible, persistent, and task-scoped.
- [shadcn/ui sidebar blocks](https://ui.shadcn.com/blocks/sidebar): grouped navigation, command/search affordances, and compact app-shell primitives.

## Information Architecture

The project sidebar now owns only project-level identity and workspace navigation:

- Project cover, title, current book/act/chapter label
- Project stats
- Workspaces: Overview, Plan, Write, Codex, Workshop, Review
- Footer actions: Switch Project, Settings

Removed from the project sidebar:

- The far-left single-letter global rail
- Chapter scene list
- Context Basket items
- Recent focus items

Scene rows now belong inside the Write workspace's Structure panel. Context Basket belongs inside Workshop and scene-specific context areas. Recent focus is omitted from the global shell until there is a validated product need.

The sidebar also has a dedicated collapsed state. It is not the old full sidebar compressed to a narrow strip:

- Collapsed width is `132px`, not a single-letter rail.
- Navigation rows use readable labels and fixed heights.
- Footer actions have fixed `44px` heights and cannot stretch vertically.
- Project cover art or project initials are hidden in collapsed mode; the collapsed sidebar is navigation, not branding.
- The expanded workspace gets redistributed grid columns instead of letting one panel absorb all extra width.

## Design Direction

Novel Studio should feel like a dense editorial workspace for long-form fiction:

- The manuscript is the visual center.
- Navigation is stable, quiet, and explicit.
- Lists are compact enough for authors managing books, chapters, scenes, codex entries, and reviews.
- Assistant and context surfaces are close to the work but do not dominate it.
- Technical internals stay out of primary UI copy.

No tutorial cards, implementation IDs, hashes, model payloads, prompt versions, storage paths, or developer notes should appear in the main product surface.

## Layout Baseline

### Shell

- Two-column desktop shell: project sidebar and active workspace.
- Project sidebar can collapse into a dedicated mini navigation layout.
- A top command bar gives current location, quick command/search, status, and primary actions.
- Page switching shows exactly one active workspace page.
- Medium desktop falls back to simpler two-column workspace layouts without horizontal overflow.
- Wide desktop uses the additional space for real work panels, not stretched cards.
- Focus mode is a Write editor control, not a global command-bar action. The control lives in the manuscript toolbar and changes to `Exit Focus` while active.

### Write

Primary job: select a scene, write prose, and keep local story context nearby.

Layout:

- Structure panel: book/act/chapter/scene hierarchy.
- Chapter Flow panel on wide screens: adjacent scenes and chapter order.
- Manuscript workspace: scene title, metadata, prose surface, save bar.
- Scene Brief panel: intent, conflict, cast, continuity.
- Open Threads panel on wide screens: promises, risks, and relationship tension.
- Focus action appears only inside the manuscript toolbar. It hides project/sidebar/supporting panels and remains available as `Exit Focus` while focused.

The scene list is not global navigation. It is part of Write.

### Plan

Primary job: compare and adjust story structure.

Layout:

- Storyboard, Outline, Matrix, and Timeline modes.
- Dense scene cards grouped by narrative structure.
- Right inspector for selected scene fields.
- Filters for status, POV, and placement.

### Codex

Primary job: edit story knowledge deeply without losing writing context.

Layout:

- Compact entry browser.
- Dense Entry Index as the default surface.
- Entry details open only after selecting an entry.
- Selecting the same entry again hides the detail surface.
- Detail surface uses separate Details, Research, Relations, Mentions, Tracking, and Progressions tabs.
- When details are open, Entry Index changes to a compact list so the detail workspace owns the main width.
- Entry Index does not show loose Type, Mentions, Changed, or Current Scene buttons. Type belongs in Categories, changed/current state belongs in row status, and mentions belong in the entry detail tabs.

Codex must assume hundreds of entries; sparse cards are not acceptable for high-volume navigation.

### Workshop

Primary job: conduct assistant sessions with explicit context.

Layout:

- Sessions and branches.
- Chat transcript and composer.
- Context Basket with grouped selections.

Context Basket is a Workshop tool, not a project sidebar list.

### Review

Primary job: decide which proposed changes enter manuscript, plan, codex, or retry queues.

Layout:

- Decision queue grouped by issue type.
- Main comparison/edit panel.
- Evidence and impact panel.
- Wide and collapsed-sidebar states keep queue, decision, evidence, and impact visible at the same time.

### Settings

Primary job: configure model connections and assistant behavior without exposing internals.

Layout:

- Settings section list.
- Model connection list and selected model form.
- Assistant role summaries.
- Defaults panel on wide screens.
