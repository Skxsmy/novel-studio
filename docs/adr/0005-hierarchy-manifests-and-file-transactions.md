# ADR-0005：显式层级清单与可恢复文件事务

状态：已接受（2026-06-20）

## 背景

场景 frontmatter 能描述自身所属幕章，但不能可靠表达空幕、空章、用户排序和父级对子级的完整成员关系。单次结构操作还会同时修改多个 YAML/Markdown 文件；逐个写入会在进程中断后留下半完成状态。

## 决策

1. `book.yaml.actIds`、`acts/<actId>.yaml.chapterIds`、`chapters/<chapterId>.yaml.sceneIds` 是父级对子级成员关系与叙事顺序的权威清单。
2. 子实体仍保存父 ID，作为双向一致性校验；二者冲突时拒绝正常读写，不静默选择一边。
3. 改名不接受 `order`；排序只能通过接收完整、无重复排列的专用命令完成。
4. 场景移动只接收目标章。目标幕和单本由权威父链推导，调用方不能提交相互矛盾的祖先 ID。
5. 创建、重排和移动等多文件操作使用 `.studio/transactions` 中的预写日志、临时文件和备份。启动或访问作品时恢复未完成事务。
6. 提供只读层级校验，报告缺失、孤儿、重复父级、祖先不一致、顺序不一致和物理路径不一致。

## 结果

- SQLite 仍只是索引，删除后可以从文件重建。
- 文件在应用外仍可读，但手工编辑造成的不一致会被明确报告。
- M2 旧稿迁移必须先建立快照，再补齐清单并通过同一校验器。
- 当前 NS-301 明确拒绝跨单本场景移动；未来若支持，必须新增独立任务定义单本级时间线、引用和事务语义。
