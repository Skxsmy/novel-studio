# 导入导出、版本与备份规格

状态：权威功能规格  
依赖：`PRODUCT_SPEC.md`

## 1. 数据安全目标

作者必须能回答：

- 当前原稿保存在哪里？
- AI 或导入操作改变了什么？
- 能否恢复到改变之前？
- 应用或索引损坏后能否恢复？
- Word 修改怎样安全地合回项目？

自动保存、版本历史和备份是三个不同能力，界面不得混用术语。

## 2. 自动保存

- 用户停止输入后短延迟保存；切换场景和关闭窗口前立即尝试保存。
- 客户端携带 `baseRevision`，服务端比较磁盘当前 revision。
- 冲突时不覆盖，保留本地草稿并展示三方选择：磁盘版、草稿版、差异合并。
- 保存采用同目录临时文件、刷盘、原子替换。
- 索引失败不回滚已成功的原稿保存，但标记 degraded 并安排重建。

## 3. Revision 与快照

### 自动快照触发

- 应用 AI 正文 Proposal 前。
- 批量查找替换前。
- Word 重导合并前。
- 数据格式迁移前。
- 恢复旧版本前。

### 手工快照

- 用户可命名“第一稿完成”“编辑返修前”等里程碑。
- 章节完成可提示但不强制建立版本。

### 不应建立快照

- 每次按键或每次自动保存。
- 纯索引重建。
- 未应用的 Proposal。

历史必须记录受影响实体、来源动作和时间。恢复前先建立当前状态快照，避免恢复成为不可逆操作。

## 4. 备份

- 首次启动选择独立备份目录。
- 可按时间或关闭应用时检查备份。
- 备份包含全部权威文件、Proposal、历史和必要配置，不要求包含可重建索引和大型缓存。
- 使用临时目录完成后再标记备份成功。
- 保留策略按数量和时间配置；删除旧备份前确认至少存在一个可验证完整备份。
- 提供“验证备份”和“从备份恢复到新目录”，默认不覆盖现有作品。

## 5. Markdown 导入

- 支持单文件和目录。
- 标题层级映射为幕/章/场景前提供预览。
- 场景分隔符可配置。
- 无法识别结构时可导为一章一场景，不擅自切分。
- frontmatter 与应用 Schema 冲突时展示字段映射。

## 6. DOCX 初次导入

流程：

1. 复制原始 DOCX 到导入暂存区。
2. 安全解析为语义 HTML。
3. 将 Word 标题样式映射为书/幕/章/场景候选。
4. 展示树形预览、正文片段和警告。
5. 用户调整识别结果。
6. 确认后创建项目并保存导入报告。

首版保留：标题、段落、粗体、斜体、场景分隔、链接和基础列表。复杂字体、页边距、页眉页脚、浮动图片和精确分页不作为原稿语义。

## 7. DOCX 导出

- 可导出整本、章节范围或选中场景。
- 使用 Word 标题样式表达书、幕、章和可选场景标题。
- 每个场景写入不可见稳定书签 ID。
- 正文应用可选导出模板，但不修改 Markdown 原稿。
- 导出报告记录作品 revision、场景顺序、书签映射和模板版本。

## 8. Word 往返

### 重导匹配优先级

1. Novel Studio 场景书签。
2. 导出报告中的内容指纹。
3. 章节/场景标题与邻接顺序。
4. 文本相似度候选。

自动匹配必须有置信度；低置信度要求人工选择，不能创建重复场景后假装成功。

### 差异审阅

- 按场景展示新增、删除、移动和修改。
- 场景拆分/合并作为显式结构操作。
- 用户逐场景或整章接受。
- 接受前创建快照。
- 原始 Word 文件与导入报告保留在历史中。

### 首版不支持

- 解析 Word Track Changes 的作者与接受状态。
- 将 Word 批注变为应用评论。
- 复杂出版排版无损往返。

## 9. Markdown 与 DOCX 导出边界

- NS-410 起，内部正文权威是 JSON `SceneBlockDocument`。Markdown 是可迁移原稿、镜像和导出格式，不再是内部正文权威格式。
- DOCX 是交稿、外部编辑和普通阅读格式。
- PDF/EPUB 不是首版权威导出；以后只能作为阅读副本，不能成为编辑往返源。
- 从 block document 导出 Markdown 时，普通正文必须保持可读；Codex progression block 默认不污染正文，可在后续导出设置中选择输出为注释或附录。

## 10. 数据迁移

- 所有 JSON 权威文件和数据库结构带 `schemaVersion`。
- 迁移分“分析 → 备份 → 执行 → 验证 → 提交”五步。
- 中途失败打开旧格式只读模式并提供恢复。
- 不允许应用启动时无提示批量重写全部作品。
- 每个迁移使用真实旧版 fixture 和回滚测试。

## 11. 验收场景

1. AI 候选应用前自动快照，恢复后原文和 metadata 都一致。
2. Word 导出后改写两个场景、改名一个章节，重导按书签正确匹配并展示差异。
3. 删除 Word 书签后使用标题与指纹生成需要确认的候选匹配。
4. 外部修改 Markdown 后保存发生 revision 冲突，不覆盖任一版本。
5. 从独立备份恢复到新目录并重建索引后，作品和历史可读。
6. 数据迁移失败时原项目未被部分升级。
