# 资料分析库规格

状态：权威功能规格  
依赖：`PRODUCT_SPEC.md`

## 1. 目标与边界

资料库用于摄入和分析用户已经获得的小说、论文、网页存档、数据说明及外部 AI 研究报告。它必须提供可追溯证据，而不是伪装拥有高质量联网搜索。作者可以在同一个作品库中建立多个互相隔离的 `Research Database`；知识库不属于任何 Series。

首版不内置 Tavily、Firecrawl、自动联网研究或后台浏览器抓取。作者明确提交一个网页地址时，可以启动一次受控网页获取；它必须保存原始地址、获取时间、响应事实和不执行脚本的原文快照，并经过与文件导入相同的来源、权限、资源和安全检查。链接导入不能扩展成自动跟踪站点、递归抓取或静默联网搜索。

### 1.1 Research Database

- `Research Database` 是作品库级权威对象；没有打开 Series 时也可以创建、选择和管理。
- 一个作品库可以有多个知识库。每个知识库拥有独立目录、元数据、SourceDocument、受管理原件、事务、解析结果和可重建索引；一个知识库损坏、重建或删除时不得影响其它知识库。
- 一个知识库可以显式关联多个 Series。Series 只引用知识库，不拥有、复制或移动知识库内容；解除关联不删除任何来源。
- 重复内容检测、来源 ID、权限、解析、索引和生命周期命令只在当前知识库内生效。同一文件可以由作者有意导入两个隔离知识库。
- 默认检索当前选中的一个知识库。作者明确多选时才允许查询层联合检索；联合检索必须给每条结果标明知识库，且不能合并权威文件、索引、权限或生命周期状态。
- NS-602 按 Series 保存的旧来源属于迁移输入。迁移必须由作者明确启动，复制并验证到选定知识库，且在另行批准清理前保留旧文件作为回滚来源。

## 2. SourceDocument

每个来源保存：

- 稳定 ID、显示名称、作者、语言和来源类型。
- 原始文件副本或受管理路径。
- SHA-256、大小、导入时间和解析器版本。
- Research Database 归属、可选 Series 关联与标签。
- AI 上下文权限：允许手动选择、允许按规则进入上下文、或禁止 AI。
- 解析状态、警告和失败原因。
- 版权/使用备注，由用户自行填写。

原始文件不可由分析过程改写。相同哈希再次导入时提示复用或建立新版本。

### 2.1 独立页面与属性管理

`Research` 是应用壳左侧主导航中的独立工作区，固定在 `Review` 之后、`Settings` 之前。它不是 Settings 的资料选项、Workshop 的附件列表，也不是 Codex Research 字段的替代品。

页面使用一个连续的资料管理工作区：知识库选择器位于来源架之前；左侧来源列表只显示当前知识库的来源；中间区域显示选中来源的标题、解析状态、原文结构/预览和后续检索入口；右侧属性区编辑显示名称、作者、声明语言、标签、人工智能上下文权限和版权/使用备注。来源类型、原始文件名、大小、导入时间、内容哈希、解析器版本与错误详情来自实际导入记录并保持只读。上传是当前知识库级明确动作；上传成功后新来源立即进入当前知识库列表并成为当前选择，刷新或重启后仍可打开。创建、选择和编辑知识库不要求打开 Series；打开 Series 时只额外显示当前知识库与该 Series 的关联状态。来源详情或正文分页发生暂时读取失败时，列表中仍存在的 Source 和持久化选择必须保留，并在对应的详情或分页区域提供真实重试；只有明确的 `404 NOT_FOUND` 才按已消失对象执行来源架回退。

页面只启用已有真实解析器、存储命令和错误路径覆盖的格式。NS-604 已接通文件或网页地址导入、结构化阅读、当前知识库关键词搜索、精确结果定位、旧来源显式升级和索引重建。永久删除、归档、重新抓取、批量编辑、语义搜索和多知识库联合查询只有在各自权威生命周期与后端命令实现并验收后才出现为可用操作。

“Research Database” 是完整产品目标的名称，不代表当前每一层已经实现。当前
NS-604 只负责可靠来源权威、原文结构、单库词法索引和作者阅读路径。NS-605
负责多数据库混合与跨语言检索服务，NS-606 负责受权限和预算控制的人工智能
只读工具网关，NS-607 负责 Workshop 会话激活与模型迭代工具循环，NS-608
负责真实保存密钥、多会话多轮作者工作流和大语料恢复/性能验收。任何较早切片
通过都不得写成“数据库全部功能已实现”。

NS-605 在现有连续 Research 工作区内增加检索范围和检索方式，而不是另建搜索
后台。默认范围仍是当前 Research Database；只有作者在搜索栏旁的范围菜单中
勾选多个数据库后，联合搜索才会打开这些独立索引。菜单必须持续显示已选数量，
每条结果必须显示所属数据库，点击结果会切换到其数据库和 Source，并打开包含
原始命中位置的分页。打开 Series、数据库之间的关联和上次搜索都不能自动扩大
下一次检索范围。

作者可在每个数据库的设置中管理持久别名和转写对。每一对都记录查询词、扩展词、
`alias` 或 `transliteration` 类型、两侧语言和备注；它们只扩展该数据库的查询，
不会写入 Source、伪装成原文或跨库共享。检索方式使用 `Hybrid` 与 `Exact` 两段
选择：`Exact` 只执行原文关键词和作者确认的别名/转写；`Hybrid` 仅在当前绑定的
Embedding profile 已通过中日英能力夹具且该数据库向量为最新时增加 semantic
通道。缺少配置、验证失败、索引陈旧、数据库损坏或部分 Source 不允许模型传递时，
页面必须逐项显示实际降级和被排除范围，同时继续返回可用的精确结果。

联合结果采用确定性融合、去重、最低相关性、来源多样性和有界分页。结果显示实际
执行的 `keyword`、`alias`、`transliteration`、`query-translation` 或 `semantic`
通道及可读分数组成；查询翻译和 Embedding 只是召回手段，Evidence 永远是未修改
的原文、当前 Source revision/hash、语言和 SourceLocation。查询翻译没有默认模型，
只有显式版本化绑定、语言对许可和查询隐私检查都通过时才执行，失败时不得静默改用
其它 Provider。

NS-602 的第一条实现切片只接受不超过 5 MiB 的 UTF-8 `.txt` 和 `.md` 文件，并把来源保存在 Series 目录。NS-603 将该路径迁移为作品库级隔离知识库。NS-604 将单个来源上限提高为 25 MiB，并交付 SourceDocument version 3：受管理原件保存在 `originals/`，有结构解析权威保存在 `content/`，`sources/` 保存不可变导入事实、作者属性、`researchDatabaseId`、路径、哈希和 revision。25 MiB 内的有效大文本必须采用近似线性的单次扫描、对超长段落和大量短段落都有效的有界 Block/Chunk 构建、轻量导入响应和分页阅读；页面不得把完整 Chunk 索引或无界 Block 数组一次发送和渲染。原件、来源与解析内容在同一个可恢复文件事务中提交；服务端复核扩展名、媒体类型、规范 Base64、声明字节数和完整字节 SHA-256，相同内容哈希只在当前 Research Database 内判重。version 2 来源只在作者明确执行升级后转换，并保留精确回滚 JSON 和不变的原件。

## 3. 支持格式

### TXT / Markdown

- 识别 UTF-8、UTF-16、GB18030、Big5、Shift_JIS 和 Windows-1252；有效 UTF-8 优先于启发式旧编码，非 UTF-8 解码会写入导入警告。
- Markdown 保留标题层级、段落、列表和引用；嵌入 HTML 不会作为活动内容执行。
- 解析结果生成稳定的 Section、Block、Chunk、行号/段落位置和语言片段，同时保留精确原始字节。

### DOCX

- 使用语义样式识别标题、段落、列表、引用和表格单元格。
- 默认禁用外部文件访问。
- 复杂排版、文本框顺序和样式丢失写入导入报告。

### 文本型 PDF

- 保存页码和页内顺序。
- 页面无可提取文本时标记“可能需要 OCR”，不输出空白成功结果。
- 不在首版执行 OCR。

### EPUB

- 验证压缩比、文件数量、路径逃逸和总体解压大小。
- 保留 spine 阅读顺序、章节标题和正文位置。

### HTML

- 清洗脚本、样式、事件属性和危险 URL。
- 不加载外部图片、字体、iframe 或脚本。
- 保留标题、正文和链接文字；网页快照另保存原始与最终来源 URL 事实。

### 网页地址

- 只在作者明确提交一个 `http` 或 `https` 地址后执行一次受控获取；不自动搜索、不递归跟踪链接、不持续监控页面。
- 限制重定向次数、响应大小、解析时间和允许的内容类型；拒绝本机、局域网、凭据化地址和其它不能安全获取的目标。
- 保存最终地址、重定向链、获取时间、响应媒体类型、内容哈希和清洗后的原文快照。后续分析只读取受管理快照，不在每次查询时重新访问网页。
- 网页更新不会静默覆盖旧来源；重新获取必须创建可审查的新版本或经过明确确认的替换操作。

## 4. 解析结果与定位

解析生成层级结构：

`SourceDocument → Section/Chapter → Block → Chunk`

每个 Chunk 包含：

- 来源 ID 和解析版本。
- 章节、页码、段落或 DOM 路径等 `SourceLocation`。
- 原文和标准化搜索文本。
- 前后文引用。
- BCP 47 语言标签、语言检测来源/置信度/检测器版本；混合语言 Chunk 还保存句子或更小边界的语言片段。
- 内容哈希和顺序。

分析结论必须引用 Chunk 或更精确位置。仅有文档 ID、不含位置的引用不满足证据要求。

## 5. 检索

### 关键词

- 当前知识库索引健康时 FTS5 可用；缺失、过期或损坏时界面显示原因并提供显式重建，不以空结果伪装健康。
- 中文和日文使用适合连续文本的字符 n-gram 基线；英文使用独立的 Unicode 词项索引。混合语言文本按带原文偏移的语言片段进入对应索引。
- 原文必须逐字保留。NFC、兼容字符折叠、大小写折叠和转写只生成带版本的搜索派生字段，不得覆盖原文；不得为了搜索统一而无条件删除日文读音符号、英文重音或其它有语义的字符。
- Codex 名称和资料元数据可保存带语言标签的作者确认别名、原名、译名、假名读音和罗马字。自动转写只能扩展搜索，不能被当作已确认名称或证据。
- 搜索 API 支持作者、标签、语言和来源类型过滤；当前 NS-604 页面只暴露当前知识库关键词框和结果打开路径。
- 结果高亮并显示来源位置。

关键词检索只承诺原语言、别名和转写命中。中文关键词与没有共享词项的日文或英文段落之间不存在可靠词法匹配；产品不得把“没有关键词结果”描述成跨语言资料不存在。

### 语义

- 默认不开启，用户配置本地或云端 Embedding 后启用。
- 本地模型以可选下载形式提供，不把大型模型捆进基础安装包。
- 云端 Embedding 必须遵守作品和资料源权限。
- Embedding 通过全局 `EmbeddingModelProfile` 调用，不复用生成模型 `ModelProfile` 的 prompt/角色配置。资料库语义检索可以绑定自己的 profile，不得阻塞 Codex schema planner、上下文检索或其它 embedding use case。
- Embedding 记录 profile、模型、维度、归一化策略、版本和 Chunk 哈希；任一变化触发对应重建。
- `EmbeddingModelProfile` 还记录声明的 BCP 47 语言覆盖、是否声明跨语言共享向量空间、模型输入前缀/规范化规则和能力来源。只有通过 Novel Studio 中/日/英交叉查询 fixture 的精确 profile 版本才能标记为 `crossLanguageReady`；声明未知或验证失败时仍可作为普通单语 profile，但不得承诺跨语言召回。
- 向量索引是可重建数据，不是资料来源。删除向量索引后必须能从 SourceDocument/Chunk 权威记录重新生成。

### 跨语言查询

跨语言查询采用可解释的混合管线，而不是预先把全部资料翻译成中文：

1. 检测查询语言，并保留作者输入的原始查询。
2. 执行原文关键词、短语和字段过滤。
3. 使用作者确认的多语言实体别名，并可加入带来源标记的确定性转写变体。
4. 当绑定的 Embedding profile 已通过目标语言对验证时，在同一 profile 和同一向量空间中执行跨语言语义召回。
5. 可选的查询翻译只扩展目标语言关键词召回。它使用应用维护的版本化翻译任务和显式选择的模型连接，不要求作者编写提示词，不发送候选来源正文，也不在失败时静默切换 Provider。
6. 各语言、各检索通道先在本通道内排序，再使用确定性的 rank fusion 合并；不得直接比较不同 FTS/模型未经校准的原始分数。
7. 按 Source/Chunk 去重，并返回原文、BCP 47 标签、原文位置、命中通道、查询变体语言和所用 profile/version。

结果阅读可提供按需译文，但发送原文给翻译模型前必须再次检查资料权限。译文明确标注为派生内容并关联原文 Chunk/hash；分析引用和 Evidence 始终锚定原文。没有可用跨语言 profile 或查询翻译时，系统继续提供原文关键词检索，并明确说明跨语言语义能力未启用。

### 混合排序

关键词、别名、转写、查询翻译和语义结果合并时显示命中方式。语义相似或翻译命中不能被描述为原文直接支持；回答仍需引用实际文本。

## 6. 分析能力

可对选择的资料执行：

- 结构与章节功能分析。
- 人物弧、关系和出场分布。
- 主题、意象和母题追踪。
- 节奏、场景长度和叙述视角分析。
- 语言与文风特征提炼。
- 事实整理、观点分歧和未知项。
- 与当前作品的对照问题清单。

分析输出包含：结论、证据、适用范围、不确定项和模型信息。不得自动把参考作品的具体措辞加入生成 Prompt。

## 7. Research Note 与 Canon

- 原文资料属于 Source。
- 从资料提炼出的内容属于 Research Note。
- Research Note 默认不是故事事实。
- “转入 Codex”产生一个新的 Proposal，并要求作者说明它是现实参考、世界规则还是仅供灵感。
- 来源更新后，已有 Research Note 不自动改写；系统提示证据版本已变化。

## 8. 外部研究报告

由 Codex、其他 AI 或人工完成的报告可作为普通 Source 导入。报告中已有的链接和引用只是文本，除非解析器能验证并定位原始来源，否则不得提升为“已核实证据”。

## 9. 安全限制

- 每种格式有文件大小、解压大小、文件数量、解析时长和内存上限。
- 解析在工作线程或子进程中执行，可超时终止。
- 禁止路径穿越和符号链接逃逸。
- 不执行宏、脚本、嵌入对象和外部资源。
- 原始资料不能覆盖作品文件。

## 10. 验收场景

1. 导入包含中文、日文和英文以及段内混合语言的 EPUB 后，可按章节、语言和原文关键词检索并回到精确原文位置。
2. 文本型 PDF 结果带页码；扫描 PDF 明确提示需 OCR。
3. 禁止 AI 的资料可关键词搜索，但不会进入本地或云模型上下文。
4. 资料进入 Embedding 或模型调用前必须经过作者选择和资料权限检查；`never` 资料在发送前被阻止。
5. 删除索引后可从 Source 重新解析/索引，不丢失 Research Note。
6. 恶意 EPUB 路径、HTML 脚本和 DOCX 外部文件引用被拒绝或隔离。
7. 使用中文查询可通过已验证的多语言 Embedding 召回不含共享词项但语义相关的日文和英文 Chunk；结果展示原文、原文位置、语言和语义命中方式。
8. 未配置或未通过验证的跨语言 profile 时，同一查询只返回可证明的关键词/别名/转写结果，并明确提示跨语言语义检索未启用，不伪造空结果结论或静默调用云模型。
9. 日文人名的作者确认汉字、假名、罗马字和中文译名可互相召回；自动转写结果与作者确认别名可区分，歧义不会自动合并实体。
10. 按需译文与原文并列且带模型/profile/version；复制引用、生成 Evidence 和跳转始终使用原文 Chunk/hash/SourceLocation。
