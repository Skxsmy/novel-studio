# M5 Workshop, Proposal, And Review Milestone

Status: milestone_in_progress
Created: 2026-06-30
Acceptance: `docs/testing/M5_ACCEPTANCE.md`

M5 is a milestone container, not a commit identity. Its product-mainline slices use NS-5xx in order. Supporting governance work uses a separate namespace and does not consume an NS number.

## Objective

Deliver an author-controlled loop in which Workshop and editorial analysis produce auditable candidate changes, Review presents the actual difference, and only an eligible Proposal or explicitly authorized safe tool command can modify authority data.

## Milestone Product Loop

```text
Workshop/analysis/import/manual source
  -> ContextBundle + ModelCallLog where applicable
  -> Proposal or server-owned tool request
  -> Review/author confirmation
  -> stale/permission/reference validation
  -> snapshot + domain/repository command
  -> authority update and source status
```

## Durable Invariants

### Proposal And Review

- Proposal extends one shared contract and records source, generator, target, base revision, patch, evidence, and decision history.
- Proposal authority is schema-versioned JSON; corrupted records are isolated without hiding valid inbox items.
- Stale or unavailable targets cannot be silently applied.
- Accepted writes create required snapshots and use domain/repository commands rather than direct file writes.
- Review is a pending decision workspace centered on before/after differences, not an engineering dashboard.
- Audit fields remain reachable in details but do not occupy the author-facing decision path.

### Workshop

- Sessions, messages, branches, attachments, context selections, and tool protocol records persist as schema-versioned JSON.
- Chat and Agent are fixed session kinds. Chat has a fully visible discussion Prompt and no write/Proposal actions.
- Context comes from explicit selection, current message attachments, and same-session history; there is no implicit current-scene binding.
- Provider-bound content matches visible context selection and excludes forbidden/future data.
- Branch, resend, delete, archive, and export preserve or explicitly block protected audit references.
- Attachments are Workshop context, not Reference Library SourceDocuments.
- Reasoning and prompt audit are explicit optional surfaces and are not mixed into ordinary answer/history output.

### Agent Tools

- Provider prose or simulated “Tool Call” text is never executable protocol.
- Tool requests are server-owned structured records.
- No tool writes authority without an explicit valid author confirmation/Grant.
- Tool execution validates identity, permission, target revision, scope, references, and lifecycle state.
- Safe adapters call existing domain/repository commands; multi-object changes are atomic or report exact partial results without false completion.
- Unsupported, dangerous, or broad mutations fall back to Proposal or require a narrower renewed approval.

### Council And Batch

- Council first-round roles are independent and cannot see one another's initial output.
- Council summaries cite existing opinions/evidence and do not introduce unchecked conclusions.
- Batch operations include only eligible Proposals and report completed, skipped, failed, and blocked items.
- Council, Workshop, and Review preserve future-story, permission, and character-knowledge isolation.
