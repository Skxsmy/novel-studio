# NS-404：模型设置、凭据边界与 Provider 选择

## 2026-07-01 Repair Note

The active implementation has been repaired beyond the original minimum NS-404 behavior:

- Model settings and service keys are library-global, not series/project-bound.
- Cloud/local policy has been removed rather than hidden.
- Save Setting preserves saved keys when the key field is empty and saves a newly typed key through the credential endpoint.
- Profile create/update payloads reject `credentialRef`; credential endpoints own key lifecycle.
- Settings controls for key save, connection test, and provider model fetch are usable without opening a project.
- Provider model fetch results are collapsed by default when large and expand into a bounded scroll list.

状态：完成。

## 目标

建立 M4 的模型配置入口和安全边界，让后续非写入型 AI 调用可以在明确权限下选择模型，而不是把供应商、密钥和回退规则散落在代码里。

## 已交付

- 新增作品库级全局模型配置 API：
  - `GET /api/v1/ai/model-profiles`
  - `POST /api/v1/ai/model-profiles`
  - `PUT /api/v1/ai/model-profiles/:profileId`
  - `POST /api/v1/ai/model-profiles/:profileId/credential`
  - `GET /api/v1/ai/model-profiles/:profileId/credential`
  - `DELETE /api/v1/ai/model-profiles/:profileId/credential`
  - `POST /api/v1/ai/model-profiles/:profileId/test`
  - `GET /api/v1/ai/model-profiles/:profileId/models`
- 新增 `CredentialRefSchema`，拒绝把明显的明文密钥写入模型配置。
- Profile create/update payload 不接收 `credentialRef`；普通保存设置必须保留已保存的凭据引用，只有 credential 专用端点能保存、替换或删除服务密钥。
- 新增 `CredentialStore` 抽象与 Windows Credential Manager 实现。
  - 当前任务只建立凭据系统边界，不新增输入真实密钥的 UI。
  - 环境无法访问凭据系统时返回明确错误，不退回明文文件。
- 安全边界为 Provider 显式选择、凭据引用、资料级 `never` 排除和禁止静默回退。
- 需要服务密钥的 Provider 缺少凭据引用时会被服务端拒绝。
- Provider 不可用时不会退回 MockProvider。
- 新增设置页“模型与资料权限”：
  - 可添加本机验收模型。
  - 可建立 OpenAI / Ollama 配置占位。
  - 可保存模型名称、模型代号、能力和系统凭据引用。
  - 可执行连接测试并显示可读结果。

## 安全边界

- 不保存真实 API key。
- 不把凭据写入作品目录、调用日志、控制台输出或 Git。
- `credentialRef` 只是系统凭据的引用名称；真实密钥只能由凭据存储实现读取。普通 profile 保存不得清空已有 `credentialRef`。
- 不实现静默回退。不同 Provider 必须由配置显式选择。
- 不新增真实网络 Provider。真实 Provider 属于 `NS-408`。
