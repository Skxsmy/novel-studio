# NS-509 Durable Workshop Agent Runner

Status: complete
Created: 2026-07-13
Owner: Codex
Acceptance: `docs/testing/NS-509_ACCEPTANCE.md`

## Objective

Replace the Workshop Agent's one-shot text parser with a durable server-side run/step state machine that supports ordinary conversation, structured Codex tool requests, one bounded repair attempt, author-confirmed tool execution, automatic continuation from successful or atomically failed tool results, and explicit restart recovery without silent replay.

The canonical author-facing hierarchy remains `Series → Volume → Chapter → Act → Scene`; NS-509 does not alter hierarchy labels or compatibility mapping.

## In Scope

- Add schema-versioned Workshop Agent run and ordered step contracts with explicit running, waiting, completed, failed, interrupted, and abandoned lifecycle states.
- Persist runs under Series Workshop JSON authority with revision-protected updates, duplicate/order validation, session ownership checks, and session-level mutation serialization.
- Link Agent assistant/tool/result messages and model calls to their exact run and step.
- Use `ProviderAdapter.generateObject` when the selected profile declares structured output.
- Use a strict JSON text boundary with a visible degraded flag when structured output is unsupported; do not change Provider or model.
- Record at most one repair step for malformed Agent output and fail explicitly when repair does not validate.
- Treat normal assistant prose as a valid structured `respond` step; tools are not mandatory per Agent answer.
- Feed every confirmed Codex tool result, including an atomically failed command, back into the same run and execute the next continuation model step. A later tool request waits for a new author confirmation.
- Remove the server's hard-coded English pending-draft rewrite regex path.
- Reconcile unfinished runs and running tool executions after storage transaction recovery without replay; expose author-triggered retry for server-classified retryable interruptions and terminal abandon.
- Add focused contracts, storage, runner, route, and web tests plus regression/build/documentation checks.

## Out Of Scope

- Workshop Prompt editing, user-defined prompt creation, Prompt version management UI, or migration of code seed prompts; NS-511 owns that product surface.
- Durable Tool Plans, Grants, broad tool permissions, new mutation adapters, or Proposal fallback; NS-512 owns those boundaries.
- New Codex mutation capability beyond the existing create/update adapters.
- Agent message edit/resend.
- Automatic replay, automatic Provider fallback, cloud fallback, or inferred permission.
- Full Workshop visual acceptance.

## Logical Closure Boundary

| Boundary | Handling |
| --- | --- |
| Authoritative data | New Series `workshop/agent-runs/*.json`; existing messages, ModelCallLogs, ContextBundles, tool execution records, and Codex authority remain authoritative in their owned paths |
| Read paths | Session detail and run endpoints load ordered runs/steps and expose degraded/interrupted state |
| Write paths | Author call creates run/steps/messages; confirmed tool command remains NS-507/NS-508 atomic; continuation appends to the same run |
| Derived state | No Agent state is reconstructed from prose; UI labels derive from durable run/tool state only |
| User entry points | Existing Agent send and Codex confirm paths, plus explicit retry and abandon actions for eligible interrupted runs |
| Lifecycle | Startup/session-load reconciliation marks unfinished work interrupted; archive/delete refuse active runs and preserve protected run-linked messages |
| Migration/rollback | Existing sessions without run links continue to load as legacy history; deleting new run files rolls back only unfinished NS-509 orchestration, not Codex writes or messages |
| Fixtures | Prose-only response, one/multiple tool requests, malformed output, unsupported structured output, repair failure, provider failure, crash-state reconciliation, stale revision, retry, abandon, and damaged/duplicate run data |
| Acceptance | `docs/testing/NS-509_ACCEPTANCE.md` |

## Decisions

- One author message starts one Agent run. Continuations after tool results remain in that run.
- A run may wait for only one current author confirmation; a continuation can create the next pending tool request after the previous result.
- Structured-output repair is bounded to one additional model call. Invalid repaired output is terminal for that attempt and is never converted to prose or a tool request.
- Unsupported structured output is a visible degraded execution mode, not an error by itself and not permission to fake native tool calls.
- Storage transaction recovery completes before Agent reconciliation. A running tool execution with no committed result is marked interrupted and retryable because NS-507's command transaction is all-or-nothing; it is never retried automatically.
- Retry preserves prior steps and creates a new attempt. Abandon is terminal and does not delete history.
- No ADR is required: this task implements the existing JSON-authority, explicit-confirmation, Provider capability, and Workshop Agent architecture without changing ownership boundaries.
