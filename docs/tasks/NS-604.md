# NS-604 Reference Library Original-language Database

Status: in_progress
Created: 2026-07-19
Owner: Codex
Acceptance: `docs/testing/NS-604_ACCEPTANCE.md`

Canonical author-facing hierarchy: `Series → Volume → Chapter → Act → Scene`.

## Objective

Turn each isolated Research Database into a real original-language reference
database. Authors can import TXT, Markdown, DOCX, text PDF, EPUB, HTML, or one
explicitly submitted web address; inspect location-aware extracted content;
and search Chinese, Japanese, English, or mixed-language original text inside
the currently selected database. Every result returns to unchanged original
Evidence and never merges authority or permissions across databases.

## Recorded User Decisions

- The author accepted the connected NS-603 multi-database Research page on
  2026-07-19 and explicitly directed work to continue with NS-604.
- The author requires Word documents, PDF files, and web links in addition to
  the limited TXT/Markdown path.
- Research Databases remain library-scoped, multiple, and isolated. They do not
  belong to a Series; one database may be linked to several Series.
- Chinese-authored novels must be able to use original Japanese and English
  material. NS-604 supplies original-language parsing and keyword search;
  no-shared-term cross-language retrieval remains NS-605.
- On 2026-07-19 the author rejected the connected workflow after a 3 MiB TXT
  produced `Internal Server Error` and required Research Databases to handle
  large files. The existing 25 MiB limit is therefore a capacity promise, not
  merely a client-side size check.

## Design Direction

1. Product goal and audience: let a novelist move from a source shelf to exact
   original-language evidence without leaving the Research workspace.
2. Tone: editorial, archival, calm, and operational.
3. Layout: preserve the accepted continuous three-column workspace; add one
   compact source-acquisition menu and a stable search strip above the reader.
4. Typography: keep source text dominant; locations and match channels use the
   existing compact metadata hierarchy rather than engineering identifiers.
5. Color and surfaces: neutral paper and ink; green means parsed/indexed, amber
   means a recoverable migration or index action, and red means rejected input.
6. Motion: only source-menu, search-loading, and result-to-reader transitions;
   reduced motion removes animation without removing state.
7. Signature differentiator: every result carries a readable location ribbon
   and opens the exact Chunk in the continuous reader, making provenance visible
   as part of reading rather than a separate audit screen.

No targeted third-party UI inspiration is needed. The accepted NS-603 page and
the installed `ui-design` Skill are the design context; Figma is not used.

## In Scope

- SourceDocument version 3, versioned parsed-content authority, Section, Block,
  Chunk, SourceLocation, language span, web-origin, search, and migration
  contracts.
- Exact binary managed originals and atomic Source/content writes inside one
  Research Database.
- Bounded TXT/Markdown, DOCX, text PDF, EPUB, HTML, and controlled web snapshot
  parsing with format-specific locations and author-readable warnings/errors.
- Explicit revision-safe migration from version 2 TXT/Markdown Sources to
  version 3, with exact rollback authority and unchanged originals.
- One isolated Research SQLite index per database, with identity, checksum,
  freshness ledger, Section/Block/Chunk projections, language rows, CJK
  character search, Unicode word search, atomic rebuild, and damage recovery.
- Single-selected-database keyword search with title, author, tag, language,
  source-kind and artificial-intelligence permission enforcement.
- Connected Research UI for file or web-address import, progress/error states,
  paged structured reader locations, single-database search/results, explicit
  legacy upgrade, and degraded-index rebuild.
- Focused unit/integration/browser tests, generated real-format fixtures,
  independent API/disk/network probes, full regression checks, and records.

## Out Of Scope

- OCR or scanned-PDF recognition, legacy `.doc`, Word Track Changes, comments,
  layout preservation, password cracking, or DRM removal.
- Recursive crawling, background refresh, browser capture, automatic research,
  robots-policy interpretation, authenticated pages, or JavaScript execution.
- Embeddings, semantic similarity, query translation, result translation,
  automatic transliteration, and a promise that Chinese keywords find unrelated
  Japanese or English words. These remain NS-605.
- Explicit multi-database query fusion, global catalogs, database merge, source
  delete/archive/version replacement, or automatic sharing.
- Sending Research text into Workshop or another model flow. NS-604 enforces the
  permission boundary in its retrieval contract but does not invent a new AI
  context workflow.
- Multi-database hybrid/cross-language retrieval, model-facing read tools,
  Workshop activation/continuation, and real saved-key author workflows. These
  are separately owned by NS-605, NS-606, NS-607, and NS-608 under ADR-0021;
  passing NS-604 must never be reported as completion of those tasks.
- Changing Series manuscript authority or its derived projection database.

## Completion Criteria

- A01-A13 pass from actual evidence. A14 remains open until the author makes a
  separate connected-workflow visual decision.
- Tests and probes use temporary libraries and do not read, migrate, rebuild,
  or modify the checkout's pre-existing `data/library/`.
- Deleting a Research index and rebuilding from Source/content authority
  restores equivalent searchable rows and locations.
- Every search and Evidence result identifies exactly one Research Database,
  Source, Chunk, original hash/revision, language, and SourceLocation.
- Unsupported OCR, recursive web research, cross-language semantics,
  translations, and multi-database search do not appear as working controls.
