# GOV-002 Database Implementation Review And Hardening

Status: complete
Created: 2026-07-19
Owner: Codex
Acceptance: `docs/testing/GOV-002_ACCEPTANCE.md`
Report: `docs/testing/GOV-002_DATABASE_REVIEW.md`

## Objective

Review the complete currently implemented database surface after NS-602, find
and reproduce correctness, recovery, concurrency, security, and performance
defects, fix confirmed defects without changing JSON authority, and publish a
prioritized review report that separates completed hardening from future
product and architecture recommendations.

## In Scope

- The versioned per-Series SQLite kernel, migration ledger, connection policy,
  health classification, write lane, temporary rebuild, validation, swap,
  rollback, cancellation, and cleanup behavior.
- Existing Scene, Codex, mention, ambiguity, Context Bundle, and Model Call
  projections and every runtime database opener or direct SQL call.
- Research SourceDocument and original-file transactions, duplicate detection,
  revision conflicts, input containment, and the API-to-repository path.
- Adversarial cases for corrupt, foreign-identity, schema-drifted, legacy,
  interrupted, concurrently accessed, and partially swapped indexes.
- Low-risk implementation optimizations that have measurable or structurally
  justified value and retain the current authority contract.
- A durable report containing confirmed findings, fixes, residual risks, and
  prioritized optional recommendations.

## Out Of Scope

- Completing NS-603 through NS-605 search, parser, catalog, vector, or
  cross-language capabilities.
- Changing JSON authority schemas, importing user data, or modifying
  `data/library/`.
- Treating diagnostic review as NS-602 visual acceptance.
- Adding dependencies, cloud services, telemetry, automatic research, or
  destructive cleanup of author data.
- Accepting recommendations as product decisions without explicit user
  approval.

## Logical Closure Boundary

Canonical author-facing hierarchy remains
`Series → Volume → Chapter → Act → Scene`; the database review does not change
or expose its internal compatibility field mapping.

| Boundary | GOV-002 obligation |
| --- | --- |
| Authority | Prove JSON and managed originals remain authoritative; fixes touch only derived-index handling or validation unless separately approved |
| Read/write paths | Inventory all SQLite openers, SQL statements, rebuild callers, Research file transactions, and routes |
| Derived state | Classify and adversarially test healthy, legacy, corrupt, wrong-identity, drifted, cancelled, and interrupted indexes |
| Concurrency | Verify per-Series serialization, cross-Series independence, live-reader behavior, and cleanup after rejection |
| Migration/recovery | Verify migration identity/checksum and preserve or restore the previous readable index on every failed replacement phase |
| Security/privacy | Verify path containment, bounded upload, no source-text logging, and no user authority mutation during tests |
| Performance | Review open/prepare/rebuild behavior, lock duration, scans, indexes, cleanup, and future scaling limits |
| Documentation | Publish exact findings, evidence, fixes, residual risk, and recommendations in the named report |

## Completion Criteria

- GOV-002-A01 through GOV-002-A10 pass with exact evidence, or the task remains
  in progress with the unresolved item named.
- Confirmed defects are fixed and covered; unsupported future capabilities stay
  visibly deferred.
- The report states what was reviewed, what changed, what remains risky, and
  which recommendations need a future user decision.
- `data/library/` and all project JSON authority remain untouched.
- The support task is committed separately from NS-514 and NS-602.
