# NS-409 Frontend Rebuild

Status: in progress, visually rejected
Updated: 2026-06-23

## Current Decision

NS-409 is still the active frontend rebuild. The current React implementation builds and has partial real API wiring, but it failed user visual acceptance. It must not be treated as passed, and later work must not proceed as if NS-409.5 succeeded.

## Scope

Rebuild the frontend into a usable author-facing application:

- Library and project creation/opening.
- Write workspace with correct story hierarchy and editing flow.
- Plan workspace with usable planning surfaces.
- Codex workspace with real entry management.
- Settings workspace with real model/profile/policy controls.
- Review and Workshop only when their workflows are real, not placeholder cards.

## Current Implementation

- `apps/web/src/app`: app shell, workspace selection, session state, text constants.
- `apps/web/src/api`: API wrappers for series, Codex, and AI/settings.
- `apps/web/src/features`: Library, Overview, Write, Plan, Codex, Workshop, Review, Settings.
- `apps/web/src/ui`: reusable primitives and tokens.
- `apps/server`: route-backed APIs for series, Codex, AI/model settings, prompts, context, and calls.
- `packages/contracts`: split domain schemas.
- `packages/storage`: repository/storage behavior, still with an oversized `src/index.ts`.

## Current Blockers

- Visual design is rejected.
- Codex is only a rough shell:
  - New Entry can be attempted,
  - entries can be loaded/selected,
  - details can be hidden by selecting the same entry,
  - full editing, relations, progressions, character knowledge, mentions, and effective-state workflows are not complete.
- Write hierarchy UX still needs product-level repair:
  - expected hierarchy is `Volume -> Chapter -> Act -> Scene`;
  - Add should open a small menu, not three permanent large buttons;
  - new items should receive default names;
  - titles should be renameable later, including double-click rename where appropriate;
  - Delete should sit beside Add and delete the selected item only after confirmation;
  - collapse behavior must not auto-center or waste space;
  - scroll must exist where content can exceed the panel.
- Settings has real API wiring but is not complete.
- Review and Workshop are incomplete.
- UI copy must be isolated for later bilingual adaptation.

## Rules For Next Contributor

- Do not read old NS-409A through NS-409F assets as current guidance.
- Do not add new status documents. Update `STATUS.md`, `HANDOFF.md`, `TASKS.md`, this file, and `docs/testing/NS-409_ACCEPTANCE.md`.
- Do not delete `docs/design/**/backups/`.
- Do not claim visual acceptance unless the user accepts it.
- Do not use DOM checks or screenshots alone as acceptance.
- Do not let `apps/web/src/app/app-shell.css` become the new monolithic stylesheet.
- Do not grow `apps/server/src/app.ts` or `packages/storage/src/index.ts` when adding domain behavior.

## Acceptance

NS-409 can pass only when:

- User accepts the visual direction.
- Library, Write, Plan, Codex, Settings, Review, and Workshop either work as scoped product flows or honestly show unavailable states.
- Codex entry workflows are real enough to create, edit, inspect, and collapse detail sections.
- Write hierarchy creation, deletion, rename, collapse, and scroll behaviors are usable.
- Commands pass:

```powershell
npm.cmd run test -w @novel-studio/web -- AppShell.test.tsx
npm.cmd run build
git diff --check
```

Current acceptance status is recorded in `docs/testing/NS-409_ACCEPTANCE.md`.
