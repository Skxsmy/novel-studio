# NS-408：真实 Provider 接入

状态：进行中。当前完成 OpenAI-compatible / DeepSeek 路径；其余 Provider 仍待实现。

## 目标

在统一 `ProviderAdapter` 下接入真实模型服务，让后续上下文装配、提示词渲染、流式调用和调用日志不再只能依赖 `MockProvider`。

首条真实路径采用 OpenAI-compatible 协议，并以 DeepSeek 作为用户后续手动填入密钥后的真实测试对象。

## 本阶段已实现

- 新增 `OpenAiCompatibleProvider`。
- 默认注册 `mock` 与 `openai-compatible` 两个 Provider。
- 支持 OpenAI-compatible 服务：
  - 连接测试；
  - 模型列表；
  - 流式文本；
  - 基础结构化输出；
  - 本地 token 粗估；
  - 统一错误分类。
- DeepSeek 快速配置入口：
  - 默认服务地址：`https://api.deepseek.com`；
  - 默认模型代号：`deepseek-v4-flash`；
  - 上下文窗口声明：`1,000,000 tokens`。
- API Key 保存入口：
  - 用户在设置页输入；
  - 服务端写入 `CredentialStore`；
  - 模型配置只保存凭据引用；
  - 输入框保存后清空；
  - 明文密钥不写入作品目录、日志或 Git。
- 后端路由统一使用注入的 `ProviderRegistry` 和 `CredentialStore`，避免测试或后续 Provider 接入时依赖模块级单例。
- 浏览器验收截图改为每次生成唯一运行 ID、唯一文件名和 `*-screenshot-manifest.json`，避免同名截图被误认为最新证据。

## 本阶段未完成

- 未实现独立 OpenAI、OpenRouter、Anthropic、Gemini、Ollama adapter。
- 未使用用户真实 DeepSeek 密钥完成端到端真实网络调用；需用户在界面保存密钥后再测试。
- 未提供完整 Provider 回退链 UI。
- 未提供完整调用记录浏览界面；仍属 `NS-409`。
- 未实现 provider-specific tokenizer；当前仍是统一粗估。

## 用户界面边界

设置页只应展示用户当前需要做的事：

- 选择或新增模型配置；
- 填写服务地址和模型代号；
- 允许云端调用；
- 保存服务密钥；
- 测试连接。

开发者边界、失败回退、日志脱敏、调用哈希、提示词版本、上下文快照等审计信息不得塞进主界面。需要展示时应进入“高级信息”、调用记录、帮助页或任务文档。
