# NS-408：真实 Provider 接入

状态：进行中。当前完成 DeepSeek、OpenAI、OpenRouter、Ollama、Anthropic、Google Gemini 与通用 OpenAI-compatible 基础路径；真实外部非写入调用验收仍待完成。

## 目标

在统一 `ProviderAdapter` 下接入真实模型服务，让后续上下文装配、提示词渲染、流式调用和调用日志不再只能依赖 `MockProvider`。

首条真实路径采用 DeepSeek 官方 OpenAI 格式接口，但在数据模型和 ProviderRegistry 中作为独立 `deepseek` Provider 管理；通用 `openai-compatible` 只表示用户自行填写服务地址的兼容服务，不继承 DeepSeek 默认地址、模型或错误语义。

## 本阶段已实现

- 新增 `OpenAiCompatibleProvider` 传输层，并用它分别承载 `deepseek`、`openai`、`openrouter`、`ollama` 与通用 `openai-compatible`。
- 新增独立 `AnthropicProvider`，使用 Anthropic Messages API，而不是冒充 OpenAI-compatible。
- 默认注册 `mock`、`openai-compatible`、`deepseek`、`openai`、`openrouter`、`ollama`、`anthropic` 与 `google` 八个 Provider。
- 支持 DeepSeek、OpenAI、OpenRouter、Ollama、Anthropic、Google Gemini 与通用 OpenAI-compatible 服务：
  - 连接测试；
  - 模型列表；
  - 流式文本；
  - 基础结构化输出；
  - 本地 token 粗估；
  - 统一错误分类。
- DeepSeek 快速配置入口：
  - 默认服务地址：`https://api.deepseek.com`；
  - 默认模型代号：`deepseek-v4-flash`；
  - 上下文窗口声明：`1,000,000 tokens`。
- OpenAI / OpenRouter / Ollama 快速配置入口：
  - OpenAI 默认服务地址：`https://api.openai.com/v1`；
  - OpenRouter 默认服务地址：`https://openrouter.ai/api/v1`；
  - Ollama 默认服务地址：`http://localhost:11434/v1`；
  - OpenAI 使用官方 Chat Completions 的 `developer` + `user` 消息结构和 `max_completion_tokens`；
  - OpenRouter 解析官方模型列表的 `data[].name` 与 `data[].context_length`；
  - Ollama 不强制保存服务密钥，默认走本机 OpenAI-compatible endpoint。
- Anthropic 快速配置入口：
  - 默认服务地址：`https://api.anthropic.com`；
  - `GET /v1/models` 使用 `x-api-key` 与 `anthropic-version: 2023-06-01`；
  - `POST /v1/messages` 使用 `model`、`max_tokens`、`system`、`messages` 和 `stream`；
  - 流式文本解析 `content_block_delta` / `text_delta` 事件；
  - 模型列表使用 `data[].id/display_name/max_input_tokens` 并支持基于 `has_more/last_id` 的分页读取。
- Google Gemini 快速配置入口：
  - 默认服务地址：`https://generativelanguage.googleapis.com/v1beta`；
  - `GET /models` 使用 `pageSize/pageToken` 分页和 `x-goog-api-key`；
  - 模型列表使用 `models[].baseModelId/name/displayName/inputTokenLimit/supportedGenerationMethods`，并只暴露支持 `generateContent` 的模型；
  - `POST /models/{model}:streamGenerateContent?alt=sse` 使用 `contents`、`systemInstruction`、`generationConfig` 和 SSE；
  - `POST /models/{model}:generateContent` 使用 `generationConfig.responseMimeType = "application/json"` 完成基础结构化输出。
- DeepSeek 与通用兼容服务已拆分：
  - DeepSeek 使用 `provider: deepseek`；
  - 自定义兼容服务使用 `provider: openai-compatible`；
  - 通用兼容服务没有 DeepSeek 默认模型，必须由用户填写服务地址或从服务端模型列表选择。
- API Key 保存入口：
  - 用户在设置页输入；
  - 服务端写入 `CredentialStore`；
  - 模型配置只保存凭据引用；
  - 输入框保存后清空；
  - 用户可替换、删除当前密钥，也可让模型配置复用已有凭据引用；
  - 明文密钥不写入作品目录、日志或 Git。
- 用户侧真实验收：
  - 用户已在设置页保存 DeepSeek 密钥；
  - DeepSeek 连接测试正常；
  - 能够从 DeepSeek 获取模型列表。
- 后端路由统一使用注入的 `ProviderRegistry` 和 `CredentialStore`，避免测试或后续 Provider 接入时依赖模块级单例。
- 浏览器验收截图改为每次生成唯一运行 ID、唯一文件名和 `*-screenshot-manifest.json`，避免同名截图被误认为最新证据。

## 官方 API 核对

本轮新增 Provider 只按官方文档中的 Chat Completions / OpenAI-compatible / Messages API 路径接入，不推测未声明字段：

- OpenAI：`POST /v1/chat/completions`、`GET /v1/models`、`Authorization: Bearer <key>`；请求体使用 `model`、`messages`、`stream`、`temperature`、`top_p` 和 `max_completion_tokens`。官方 Chat Completions 文档提示新模型用 `developer` 消息承载开发者指令，本实现仅 OpenAI 路径使用 `developer`。
- OpenRouter：`POST https://openrouter.ai/api/v1/chat/completions`、`GET https://openrouter.ai/api/v1/models`、`Authorization: Bearer <key>`；模型列表使用 `data[].id`、`data[].name`、`data[].context_length`，请求体使用 `model`、`messages`、`stream`、`temperature`、`top_p` 和 `max_completion_tokens`。
- Ollama：官方 OpenAI compatibility endpoint 为 `http://localhost:11434/v1` 下的 `/chat/completions` 与 `/models`；请求体沿用 OpenAI-compatible 的 `model`、`messages`、`stream`、`response_format` 等字段，本实现不要求 Authorization header。
- DeepSeek：继续使用官方 OpenAI-compatible 的 `https://api.deepseek.com/chat/completions` 与 `/models`；请求体使用 `model`、`messages`、`stream`、`temperature`、`top_p` 和 `max_tokens`。
- Anthropic：`GET https://api.anthropic.com/v1/models` 返回 `data[]`、`has_more`、`first_id`、`last_id`；`POST https://api.anthropic.com/v1/messages` 使用 `x-api-key`、`anthropic-version: 2023-06-01`、`model`、`max_tokens`、`system`、`messages` 和可选 `stream`。流式文本来自 `content_block_delta` 事件中的 `delta.text`。
- Google Gemini：`GET https://generativelanguage.googleapis.com/v1beta/models` 使用 `pageSize/pageToken`，返回 `models[]` 与可选 `nextPageToken`；`POST https://generativelanguage.googleapis.com/v1beta/{model=models/*}:generateContent` 使用 `contents`、`systemInstruction`、`generationConfig`；流式接口为 `POST ...:streamGenerateContent?alt=sse`。API key 按官方 API key 文档使用 `x-goog-api-key` header，避免把密钥放进 URL。

## 用户界面边界

设置页只应展示用户当前需要做的事：

- 选择或新增模型配置；
- 填写服务地址和模型代号；
- 保存服务密钥；
- 替换、删除或复用已保存密钥；
- 获取服务商返回的模型列表；
- 测试连接。

开发者边界、失败回退、日志脱敏、调用哈希、提示词版本、上下文快照等审计信息不得塞进主界面。需要展示时应进入“高级信息”、调用记录、帮助页或任务文档。
