# NS-401：M4 执行规格与 MockProvider 垂直切片

状态：完成。

## 目标

把 M4 从“要做 AI 能力”收敛成可执行的第一条纵向闭环：

> 模型配置草案 → MockProvider → 上下文预览 → 非写入型调用 → 调用日志 → 可审计 UI。

NS-401 只写规格、接口草案、文件格式草案和验收映射，不接真实模型，也不实现运行时代码。这样后续 `NS-402` 到 `NS-407` 可以按边界施工，而不是把 Provider、上下文、提示词和日志混进现有大文件。

## 非目标

- 不调用 OpenAI、Ollama、OpenRouter、Anthropic、Gemini 或任何真实服务。
- 不创建 API key 文件。
- 不实现候选稿应用、事实收件箱或多编辑会审。
- 不允许 AI 直接写正文、设定库、摘要、故事进展或角色所知。
- 不新增后台自动分析任务。

## 第一条垂直切片

首条切片使用 MockProvider，而不依赖真实网络：

1. 作者在当前场景选择一个已创建的自定义角色，例如上下文检查角色。
2. 前端请求上下文预览。
3. 服务端生成 `ContextBundle`：
   - 包含当前场景、规划摘要、有效设定、有效故事进展、角色所知和主动选择资料。
   - 排除 `never`、未来剧情、隐藏区段和无权限资料。
   - 给出估算用量。
4. 作者确认后发起非写入型 AI 调用。
5. MockProvider 以 SSE 返回分段文本。
6. 服务端保存 `ModelCallLog`。
7. 前端显示回复，并允许查看：
   - 实际上下文快照。
   - 提示词模板版本。
   - 模型配置和参数。
   - 请求 / 响应哈希。
   - 估算与实际用量。

该切片的输出只能显示在编辑室或调用记录中；不能改写正文、设定或任何 Canon 文件。

## 模块边界

后续实现必须按下列边界拆分：

| 领域 | 位置 | 规则 |
|---|---|---|
| 契约 | `packages/contracts/src/ai.ts`、`context.ts`、`prompts.ts`、`proposals.ts` | 不继续扩大单体 `index.ts`。 |
| Provider | 优先 `packages/ai/src/` | Adapter 不依赖 Fastify，不读写小说文件。 |
| 上下文装配 | `apps/server/src/context/` | 只读聚合；不写正文、Codex 或摘要。 |
| 提示词渲染 | `apps/server/src/prompts/` | 声明式模板；禁止执行任意 JavaScript。 |
| 调用日志 | `apps/server/src/modelCalls/` + storage 子模块 | 请求、响应、上下文、用量和错误都可追溯。 |
| API 路由 | `apps/server/src/routes/ai.ts`、`context.ts`、`prompts.ts`、`modelCalls.ts` | 路由只做 HTTP 编排，不拼接复杂提示词。 |
| 前端 | `apps/web/src/ai/`、`context/`、`prompts/` | 不把调用日志 UI 塞回 `WriteView.tsx`。 |

## API 草案

NS-402 起按 `docs/architecture/API.md` 的 M4 草案实现。第一批 API 分四组：

1. 模型配置与 Provider：
   - `GET /ai/model-profiles`
   - `POST /ai/model-profiles`
   - `PUT /ai/model-profiles/:profileId`
   - `POST /ai/model-profiles/:profileId/credential`
   - `GET /ai/model-profiles/:profileId/credential`
   - `DELETE /ai/model-profiles/:profileId/credential`
   - `POST /ai/model-profiles/:profileId/test`
   - `GET /ai/model-profiles/:profileId/models`

2. 提示词与角色：
   - `GET /series/:seriesId/ai/roles`
   - `POST /series/:seriesId/ai/roles/:roleId/clone`
   - `GET /series/:seriesId/ai/prompts`
   - `POST /series/:seriesId/ai/prompts`
   - `POST /series/:seriesId/ai/prompts/:promptTemplateId/preview`
   - `POST /series/:seriesId/ai/prompts/:promptTemplateId/versions`

3. 上下文：
   - `POST /series/:seriesId/context/preview`
   - `GET /series/:seriesId/context/:contextBundleId`

4. 调用与日志：
   - `POST /series/:seriesId/ai/calls`
   - `GET /series/:seriesId/ai/calls`
   - `GET /series/:seriesId/ai/calls/:modelCallId`
   - `GET /series/:seriesId/ai/calls/:modelCallId/context`
   - `GET /series/:seriesId/ai/calls/:modelCallId/events`

`POST /series/:seriesId/ai/calls` 的首版只允许 `taskKind=analysis|critique|continuity-check|style-review|brainstorm`，不得接受 `rewrite|continue|apply-patch` 等会诱导直接改稿的任务。

## 文件格式草案

权威格式见 `docs/architecture/DATA_MODEL.md`。NS-401 规定：

- 模型配置保存 Provider、模型、能力和凭据引用，不保存密钥明文；配置为作品库级全局 Settings，所有 project/series 共享。
- Credential 只保存引用 ID，例如 `credentialRef: novel-studio:openai:default`。
- 上下文包是调用时快照，后续设定变化不改写旧上下文包。
- 调用日志保存哈希和元数据，不保存 API key。
- 提示词模板每次修改都生成新版本。

## 安全与权限不变量

- `never` 资料不得进入上下文，即使用户主动选择也不行。
- 后文进展和未来角色所知不得向当前场景泄漏。
- 当前安全边界为 Provider 显式选择、凭据引用、资料级 `never` 排除和禁止静默回退。
- 本地 Provider 失败不得静默回退云端 Provider。
- AI 输出不得直接写入正文、Codex、摘要、进展或角色所知。
- 所有调用必须先有 `ContextBundle`，再有 `ModelCallLog`。
- 所有错误必须有分类，不能只把 SDK 原始异常抛给 UI。
