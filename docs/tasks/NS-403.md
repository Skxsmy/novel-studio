# NS-403：ProviderAdapter 核心与 MockProvider

状态：完成。

## 目标

建立统一的模型 Provider 抽象，让后续上下文装配、提示词渲染、非写入型调用和调用日志不依赖具体 SDK。

NS-403 只完成运行时内核：接口、能力描述、MockProvider、ProviderRegistry 和错误分类。它不提供模型设置界面，不读取密钥，不连接真实云端或本地模型。

## 非目标

- 不接 OpenAI、Ollama、OpenRouter、Anthropic、Gemini 或任何真实服务。
- 不实现 Windows Credential Manager。
- 不新增 `/api/v1` 模型路由。
- 不做上下文装配器。
- 不写入正文、已确认设定、摘要、故事进展、角色所知或 Proposal。
- 不把 MockProvider 的存在伪装成真实 AI 能力。

## 已完成

### 新增 AI workspace

新增 `packages/ai`：

- `ProviderAdapter` 接口。
- `ProviderRegistry` 与默认 registry。
- `MockProvider`。
- `ProviderAdapterError` 与 `classifyProviderError`。

根目录 `build:packages` 已纳入 `@novel-studio/ai`，顺序为：

```text
contracts → ai → storage
```

这样 server、context builder 和调用日志实现可以稳定依赖同一 Provider 抽象。

### ProviderAdapter 接口

`ProviderAdapter` 当前提供：

- `testConnection`
- `listModels`
- `streamText`
- `generateObject`
- `embed`
- `estimateTokens`
- `describeCapabilities`
- `classifyError`

Adapter 不依赖 Fastify，不读写小说文件，也不访问凭据系统。

### MockProvider

MockProvider 支持：

- 能力描述和模型列表。
- 连接测试。
- 流式非写入文本。
- Zod 校验的结构化输出。
- 确定性的 embedding 向量。
- 简单 token 估算。
- 模拟认证失败、限流、模型不可用、结构化输出失败、上下文过长和未知错误。

MockProvider 的输出明确标记为非写入型结果，并以 `safeToWrite: false` 约束结构化输出。它没有任何写入正文或已确认设定的能力。

### 错误分类

错误统一归类为 `ModelCallError`：

- `provider-auth-failed`
- `provider-rate-limited`
- `model-unavailable`
- `context-too-large`
- `structured-output-failed`
- `provider-error`
- `unknown`

原始错误不直接暴露给 UI；调用日志后续只应记录分类、可重试性、状态码和原始错误哈希。
