# M4：模型连接、上下文装配、提示词系统与调用审计

状态：进行中。`NS-401` 至 `NS-406` 已完成；下一步是 `NS-407`。

M4 的目标不是“让 AI 直接写小说”，而是先建立可信的 AI 基础设施：模型连接、上下文预览、权限隔离、提示词版本、调用日志和非写入型 AI 调用。任何会改变正文、设定、摘要、人物状态或故事进展的结果，都只能形成候选记录；应用候选变更属于 M5。

## M4 成功标准

- 可以配置本地与云端模型 Provider，并测试连接、列出模型和能力。
- 可以按当前场景生成 `ContextBundle`，并在调用前预览实际会发送的资料。
- 上下文装配遵守 `always / on-mention / manual / never`、未来剧情隔离、隐藏区段和角色所知边界。
- 可以管理提示词模板、角色职责、版本和预览；模板为声明式结构，不执行任意 JavaScript。
- 可以执行至少一种非写入型 AI 调用，并保存 `ModelCallLog`。
- 流式输出可以显示在界面中，但不会直接写入正文或设定库。
- 每次调用可追溯：角色、模型、参数、提示词版本、上下文包、用量估算、实际用量、请求 / 响应哈希和错误分类。
- 云端被禁用时不得发生云端请求，也不得从本地模型静默回退到云端模型。
- M4 结束时有自动化测试和浏览器验收覆盖主要路径。

## 非目标

- 不实现多编辑会审。
- 不实现 AI 候选稿应用、事实收件箱处理或自动更新设定。
- 不允许 AI 直接修改正文、已确认设定、摘要、人物状态、故事进展或角色所知。
- 不实现商业账号、订阅、团队协作或公共市场。
- 不实现内置联网搜索。
- 不把 API 密钥写入作品目录、日志、调用记录或 Git。

## 架构边界

M4 新增代码不得塞回以下大文件：

- `apps/server/src/app.ts`
- `apps/web/src/CodexView.tsx`
- `apps/web/src/WriteView.tsx`
- `packages/storage/src/index.ts`
- `packages/contracts/src/index.ts`

建议新增边界：

| 层 | 建议位置 | 职责 |
|---|---|---|
| contracts | `packages/contracts/src/ai.ts`、`context.ts`、`prompts.ts`、`proposals.ts` | AI、上下文、提示词和调用日志契约 |
| provider | `packages/ai/src/` 或 `apps/server/src/ai/` | ProviderAdapter、能力描述、错误分类、流式抽象 |
| context | `apps/server/src/context/` | 从场景、规划、设定库、进展、角色所知和主动选择资料装配 ContextBundle |
| prompt | `apps/server/src/prompts/` | 模板解析、版本、预览和角色输入 |
| routes | `apps/server/src/routes/ai.ts`、`context.ts`、`prompts.ts`、`modelCalls.ts` | `/api/v1` 接口 |
| storage | `packages/storage/src/ai/`、`prompts/`、`modelCalls/` | 模型配置、提示词文件、调用日志索引和持久化 |
| web | `apps/web/src/ai/`、`context/`、`prompts/` | 设置页、上下文预览、调用日志和流式输出 UI |

如果不新增 `packages/ai`，也必须保持 Provider 与 server route 分离；路由只负责 HTTP，不负责拼提示词或直接调用 SDK。

## 数据与文件约定

M4 允许新增：

- `.studio/model-profiles/*.yaml`
- `.studio/model-calls/*.yaml`
- `.studio/context-bundles/*.yaml`
- `prompts/templates/*.yaml`
- `prompts/roles/*.yaml`
- `prompts/presets/*.yaml`
- `workshop/*.yaml` 的最小对话记录，只限非写入型结果

M4 不允许新增：

- 明文 API key 文件。
- 会自动改写正文或设定库的后台任务。
- 无版本号的提示词模板。
- 无上下文记录的 AI 调用。

### NS-404：模型设置、密钥存储与权限开关

目标：建立模型配置 UI 与密钥安全边界。

交付：

- 模型设置页面或设置抽屉。
- 作品级云端启用 / 禁用开关。
- Provider 连接测试。
- API key 存储抽象。
- Windows Credential Manager 实现；如果当前环境无法写入凭据系统，必须有明确错误提示，不落明文文件。

- 不允许本地模型失败后静默回退云端。

状态：完成。详见 `docs/tasks/NS-404.md`。

### NS-405：上下文装配器

目标：按当前场景生成可审计的 `ContextBundle`。

输入顺序：

1. 角色职责和提示词版本。
2. 用户当前请求。
3. 当前场景目标、节拍和正文选区。
4. 相邻场景和前文摘要。
5. 截至当前叙事位置有效的设定库状态。
6. 活跃情节线、伏笔、人物知识和世界事实。
7. 风格档案与用户主动选择资料。

交付：

- `POST /api/v1/series/:seriesId/context/preview`
- 上下文条目来源、权限原因、估算 token 和排除原因。
- 未来剧情、`never` 资料、隐藏区段、无权限资料默认排除。

验收：

- `never` 即使主动选择也不进入上下文。
- 后文进展和未来角色所知不向前泄漏。
- 每个 ContextItem 都有来源 ID 和人类可读原因。
- 浏览器能在调用前预览上下文。

状态：完成。详见 `docs/tasks/NS-405.md`。

### NS-406：提示词模板、角色与版本

目标：把提示词从代码字符串变成可审计文件。

交付：

- 内置角色：
  - 主笔伙伴
  - 结构编辑
  - 人物编辑
  - 连续性编辑
  - 文风编辑
  - 冷酷读者
  - 研究员
- 角色可复制修改。
- 模板、Persona、Preset、输入项、可复用组件和版本历史。
- 模板预览，不执行任意 JavaScript。

验收：

- 每次调用记录 PromptTemplate ID 和版本。
- 修改模板会生成新版本，不覆盖旧调用记录。
- 模板渲染缺少必需输入时拒绝调用。

状态：完成。详见 `docs/tasks/NS-406.md`。

### NS-407：非写入型 AI 调用与调用日志

目标：完成 M4 第一条真实闭环：用户选择角色和模型，对当前场景发起分析请求，得到流式回复，并保存调用日志。

交付：

- `POST /api/v1/series/:seriesId/ai/calls`
- SSE 流式输出。
- `ModelCallLog` 保存：
  - 调用 ID
  - 角色 ID
  - Provider / Model
  - 参数
  - Prompt 版本
  - ContextBundle ID
  - 请求 / 响应哈希
  - token 估算和实际用量
  - 状态与错误分类
- 前端显示调用结果和日志详情。

验收：

- 调用完成后可查看实际发送上下文。
- 调用失败也保存失败日志，但不保存密钥。
- AI 结果不能直接写正文或设定。

### NS-408：真实 Provider 接入

目标：在统一 Adapter 下接入真实 Provider。

优先顺序：

1. OpenAI-compatible
2. Ollama
3. OpenAI
4. OpenRouter
5. Anthropic Claude
6. Google Gemini

交付：

- 每个 Provider 独立 adapter。
- 连接测试、模型列表、流式文本、结构化输出能力声明。
- Embedding 能力先声明；如果首版某 Provider 未实现 Embedding，必须明确返回“不支持”，不能假装可用。

验收：

- 至少 OpenAI-compatible、Ollama 和一个主流云端 Provider 可通过 Mock/单元测试验证协议层。
- 手工配置真实密钥时可完成一次非写入型调用。
- 不同 Provider 错误被归类为认证、限流、网络、模型不可用、上下文过长、结构化输出失败等。

## 推荐实现顺序

1. NS-401 文档与接口草案。
2. NS-402 契约和持久化。
3. NS-403 MockProvider。
4. NS-405 上下文装配器。
5. NS-406 提示词模板。
6. NS-407 非写入型 AI 调用和日志。
7. NS-409 UI。
8. NS-404 密钥和权限。
9. NS-408 真实 Provider。
10. NS-410 收口。

原因：先用 MockProvider 打通上下文和审计闭环，再接真实 Provider。这样不会在密钥、网络、SDK 差异里迷路，也能更早验证“AI 不可直接写入”的核心边界。

## M4 风险控制

- 每个 NS 任务必须形成一个可审查提交。
- 任何 Provider 真实 SDK 接入前，MockProvider 测试必须先通过。
- 任意新增路由必须写入 API 文档。
- 任意新增文件格式必须写入 DATA_MODEL 文档。
- 任意 AI 调用必须先生成 ContextBundle，再生成 ModelCallLog。
- 任意 AI 结果不得绕过 Proposal / 候选机制写入正文或 Canon。
