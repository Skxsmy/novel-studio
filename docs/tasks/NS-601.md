# NS-601 Database Architecture Planning

Status: complete
Created: 2026-07-18
Owner: Codex
Acceptance: `docs/testing/NS-601_ACCEPTANCE.md`

## Objective

Define a mature, implementation-ready database architecture for Novel Studio
without changing the product's JSON-authority boundary. The plan must audit the
existing SQLite/FTS5 prototype, select database topology and ownership,
describe the novel-text, narrative, multilingual, and cross-language logical
schema and lifecycle in detail, and split runtime delivery into independently
testable M6 tasks. All hierarchy projections use the canonical author-facing
order `Series → Volume → Chapter → Act → Scene`.

## Out Of Scope

- Changing JSON authority or migrating Canon into SQLite.
- Implementing database modules, SQL migrations, API routes, UI, Reference
  Library ingestion, vector search, or background workers in this task.
- Selecting or adding a native vector engine, custom Chinese tokenizer,
  encryption library, ORM, or loadable SQLite extension.
- Rewriting `packages/storage/src/index.ts` as part of documentation planning.
- Claiming NS-602 through NS-605, M6, M7, or M8 runtime behavior is complete.
- Modifying, rebuilding, or deleting the user's existing Series databases.

## Logical Closure Boundary

| Boundary | Handling |
| --- | --- |
| Authoritative data | Unchanged schema-versioned JSON and managed Source files; ADR-0012 remains controlling |
| Read paths | Planned `IndexDatabase` query facade for search, mentions, planning, audit, Reference Library, and catalog projections |
| Write paths | Plan requires authority-first commit followed by independent derived indexing; no SQLite semantic command |
| Derived state | Detailed per-Series `index.sqlite`, optional library `catalog.sqlite`, FTS5, vector metadata, and sidecar boundaries |
| User entry points | No UI in NS-601; future Settings diagnostics may expose useful rebuild/health actions without database jargon in author workspaces |
| Lifecycle | Missing, stale, rebuilding, degraded, corrupt, and authority-invalid states; atomic temporary rebuild and bounded quarantine |
| Migration/rollback | Unversioned current indexes rebuild to v1; future derived schemas migrate or rebuild; rollback never writes SQLite rows into authority |
| Fixtures | Existing real schema inventory plus future damaged, stale, concurrent, cancellation, disk/swap failure, Chinese search, and M8-scale fixtures |
| Acceptance | `docs/testing/NS-601_ACCEPTANCE.md`; documentation/source evidence only |

## Decisions And Open Questions

- Existing SQLite is a prototype to harden, not a blank slate.
- Per-Series `index.sqlite` remains the primary projection boundary. A
  library-level `catalog.sqlite` is deferred until NS-605 proves a cross-Series
  query need.
- SQLite remains the selected relational/search engine and `better-sqlite3`
  remains the planned driver; no new dependency is required for NS-602.
- WAL is retained with a fixed-version gate and one serialized writer. The
  installed SQLite `3.53.2` is newer than the official `3.51.3` WAL-reset fix.
- Current unversioned databases are disposable schema version 0. The first
  implementation builds version 1 from authority instead of migrating rows as
  unique data.
- FTS5 uses external content plus synchronization triggers and integrity
  checks. Physical indexes are split by domain and analyzer behind one query
  facade: CJK uses trigram, English uses Unicode word terms, and short query,
  field weighting, mixed-language span, and alias behavior are explicit.
- Cross-language retrieval does not pre-translate authority. Chinese queries
  combine literal search, author-confirmed multilingual aliases, search-only
  transforms, an exact fixture-validated multilingual Embedding profile, and
  optional versioned query translation. Results disclose channels and always
  cite the Japanese/English/other original.
- Full rebuild creates and validates a temporary database, then atomically
  swaps it. Clearing the live database before parsing is prohibited.
- Database schema uses canonical product terms `Volume / Chapter / Act` even
  though Storage adapters still read legacy `book / act / chapter` paths.
- Both SQLite core and FTS secure-delete are planned, but they are not disk
  encryption or forensic-erasure claims.
- Actual vector storage, final `application_id`, library catalog timing,
  analyzer dependency, default multilingual profile, and optional at-rest
  encryption remain explicit later decisions. None blocks NS-602's kernel;
  language-search implementation cannot pass NS-603/605 without its fixtures.
