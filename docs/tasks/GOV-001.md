## Objective

Make the repository's AI constraints and delivery records reliable, task-routed, and inexpensive to read. This task changes documentation governance and validation only. It does not change Novel Studio runtime behavior or project data.

## Required Reading

- `PROJECT.md` and the root operational entry documents.
- `docs/product/README.md`, `docs/product/PRODUCT_SPEC.md`, `docs/product/REQUIREMENTS_TRACEABILITY.md`, and relevant AI/UX domain sections.
- Current/target architecture, data model, API, security, and all ADR status headers.
- Current M5/NS-410 task and acceptance records as delivery-structure samples.

## In Scope

- Replace unconditional reading fan-out with task-type routing in `AGENTS.md`.
- Reserve `NS-###` exclusively for product-mainline tasks and use `GOV-###` for this support stream without consuming or renumbering the M5 mainline.
- Make `STATUS.md` the only current operational-state authority.
- Reduce `HANDOFF.md` to an interrupted-work handoff and `TASKS.md` to an index.
- Keep `README.md`, `ROADMAP.md`, and `CHANGELOG.md` free of duplicated live task state.
- Remove confirmed Markdown-authority and archive-only statements from current authoritative documents.
- Normalize ADR lifecycle metadata and supersession links.

- Add a repository documentation consistency check.
- Record the confirmed all-English product hierarchy and isolate the legacy storage mapping.

## Out Of Scope

- Runtime application code and user project data.
- M5.6B Atomic Codex adapter implementation.
- Runtime migration of legacy hierarchy field names or incomplete UI surfaces.
- Rewriting commits already present on `origin/codex/ns-410-json-authority` or force-pushing any remote branch.
- Deleting historical task, acceptance, design, or protected backup files.
- Rewriting completed historical records merely to modernize their terminology.

## Product Decision

The user decided on 2026-07-10 that the canonical author-facing hierarchy is always English and ordered `Series → Volume → Chapter → Act → Scene`. The existing storage compatibility model may continue until a separate migration, but documentation and UI must map it explicitly as `Series → series`, `Volume → book`, `Chapter → act`, `Act → chapter`, and `Scene → scene`, and must never expose the internal names as product labels.

- NS-500: M5 preparation, protection tests, and regressions required to preserve the baseline.

Before rewriting, create a local backup ref. After rewriting, require the same commit count, an empty tree diff against the backup tip, a clean upstream boundary, and an explicit before/after subject ledger.
