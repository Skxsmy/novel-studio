# NS-510 Workshop Capability And Boundary Cleanup

Status: in_progress
Created: 2026-07-13
Owner: Codex
Acceptance: `docs/testing/NS-510_ACCEPTANCE.md`

## Objective

Make the Workshop's public capabilities, persisted Agent lifecycle, author-facing controls, and implementation modules agree with the behavior the product actually supports. The first blocking repair is the real-Provider Agent continuation path: a confirmed Codex result must continue the same run, and a schema-invalid Provider JSON response must receive one evidence-based repair attempt instead of a blind retry.

The canonical author-facing hierarchy remains `Series → Volume → Chapter → Act → Scene`; NS-510 does not alter its compatibility mapping.

## In Scope

- Preserve a Provider's raw structured response in process when local schema validation fails so the bounded repair call receives the actual invalid output; persist only the existing response hash/usage and the exact repair prompt already required by the Agent run audit.
- Ensure malformed initial and continuation steps record both attempts, continue the same run when repaired, and remain explicitly retryable after one invalid repair without requiring another author message.
- Make Workshop prompt-audit export read exact durable Agent step prompt snapshots and every step-linked ModelCall instead of reconstructing continuation/repair prompts from the initial ContextBundle.
- Resolve General Chat prompt scope/session binding.
- Expose branch creation from an exact eligible message.
- Remove or quarantine unreachable legacy Proposal/context/mode capabilities and normalize Codex context grouping semantics.
- Make message deletion turn-aware or constrain it to a proven safe author-history boundary.
- Centralize Workshop copy behind an explicit language boundary.
- Split oversized Workshop frontend/server modules along existing ownership boundaries without changing behavior.
- Include `docs/design/ui-redesign/novel-studio-full-ui-redesign-reference.html` in the final task commit as explicitly directed by the author; do not rewrite its content as part of NS-510 unless a later scoped decision requires it.

## Out Of Scope

- Versioned editable Workshop Prompt authority and prompt-management UI; NS-511 owns that scope.
- Durable Tool Plans, Grants, broader mutation tools, execution approval identity, and Proposal fallback; NS-512 owns that scope.
- Council, final responsive-state sweep, and explicit user visual acceptance; NS-513 owns that scope.
- Automatic Provider/model fallback or unbounded structured-output retries.

## Logical Closure Boundary

| Boundary | Handling |
| --- | --- |
| Authoritative data | Existing Workshop sessions/messages/runs, ContextBundles, ModelCallLogs, and project JSON authority remain the only durable records |
| Provider boundary | JSON syntax capability remains distinct from local schema validation; invalid raw output is available only to the bounded repair path and exact run prompt snapshot |
| Agent lifecycle | Initial, repair, tool-result, continuation, terminal failure, retry, and restart states remain one durable run |
| Export | Prompt audit enumerates exact run steps/model calls; attachment bodies remain omitted |
| User entry points | Existing Workshop session, branch, context, delete, export, and Agent confirmation/recovery controls |
| Module ownership | Frontend and server splits preserve existing API/storage authority boundaries |
| Acceptance | `docs/testing/NS-510_ACCEPTANCE.md` |

4. Completed: A06 now exposes only six supported context refs, normalized Codex grouping, no legacy message Proposal route, and exactly the `general-chat` / `agent` Workshop modes. The two removed modes have no compatibility or migration path by author decision.
5. Completed: A07 deletes only complete settled General Chat turns and atomically cleans their attachments and branch references; Agent, pending, mixed-protocol, and Proposal-linked histories are protected.
6. Completed: A08 freezes current Workshop chrome at `en-US`, routes static labels/fallbacks/date formatting through one resource boundary, and treats editable prompt/project/model content as language-independent. Chinese localization remains future work rather than a false completion claim.
7. Completed: A09 extracts pure frontend conversation policy and view-model helpers, server record routes, and reasoning parsing behind tested ownership boundaries. The scoped split is complete; the remaining large-module risk stays recorded rather than being treated as fully eliminated.
8. Completed: A10 focused/full regression, build, legacy-surface search, documentation, and diff evidence is recorded; visual acceptance remains open for NS-513.
9. Active: run closure checks and commit only the scoped NS-510 implementation and evidence.

The current `WorkshopAgentCoordinator` is an in-process per-session serialization boundary, not the completed target coordinator. Durable wake/join, cancellation propagation, startup recovery, side-effect-unknown settlement, and broader Tool Plan/Grant execution remain open and must not be inferred from A01-A03.

## Product Decision

- `NS-510-A04`: on 2026-07-14 the author selected per-session persistence. The visible General Chat system prompt is a chat-session authority snapshot, not component-global state and not a per-call override. NS-511 may later migrate the snapshot to versioned Workshop Prompt authority without changing the session binding.

## Completion Criteria

- Every acceptance ID has actual evidence.
- No structured-output failure is reported as repaired unless the repair call received the invalid Provider response and produced a valid step; an exhausted bounded repair remains retryable in the same run.
- Prompt audit reflects durable inputs actually sent for each Agent model attempt.
- Remaining M5.6E defects are repaired or explicitly reclassified by authority, not silently dropped.
- Task-related files are committed; unrelated user changes remain untouched.
