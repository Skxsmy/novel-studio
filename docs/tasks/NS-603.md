# NS-603 Library-scoped Research Database Authority And Isolation

Status: in_progress
Created: 2026-07-19
Owner: Codex
Acceptance: `docs/testing/NS-603_ACCEPTANCE.md`

## Objective

Replace the Series-owned Research shelf with the author-approved library-level
Research Database model. An author can create multiple isolated databases,
switch between them without opening a Series, edit database properties, link
one database to several Series, and import or manage Sources only inside the
selected database. Existing NS-602 Series-owned Sources remain recoverable
through an explicit verified migration path.

This task establishes the authority and interaction boundary needed before
DOCX, text PDF, EPUB, HTML, and author-submitted web addresses are added in
NS-604. It does not pretend those formats or full multilingual search exist.

Canonical author-facing hierarchy remains `Series → Volume → Chapter → Act → Scene`.

## Recorded User Decisions

- On 2026-07-19 the author accepted the overall NS-602 Research layout and
  requested Word documents, text PDF files, and web links as real future
  inputs.
- The author then decided that a Research Database is not bound to a Series and
  that several databases must remain isolated from one another.
- The author accepted the recommendation that one database may be explicitly
  linked to several Series, and that search defaults to one database while an
  explicit future multi-selection may merge labeled results without merging
  data or permissions.

## Design Direction

1. Product goal and audience: give a novelist a reusable private research shelf
   that is independent of any one manuscript.
2. Tone: editorial, archival, precise.
3. Layout: retain the continuous reader workspace; place a stable database
   switcher above the current database's source rail.
4. Typography: existing Novel Studio hierarchy, with database identity compact
   enough to keep original text dominant.
5. Color and surfaces: existing neutral paper and ink, green only for connected
   or ready state, amber/red only for actionable state.
6. Motion: only communicate drawer, loading, and selection transitions; honor
   reduced-motion preferences.
7. Signature differentiator: changing database replaces the complete shelf
   index as one unit, making isolation visible without cards or engineering
   database terminology.

No targeted third-party inspiration is used. The existing connected Research
workspace and installed `ui-design` Skill are the design context.

## In Scope

- ResearchDatabase version 1 contract, revision response, create/update inputs,
  linked Series identifiers, and SourceDocument version 2 ownership.
- One isolated `research-databases/<database-id>/` authority root per database,
  with database metadata, Sources, originals, transactions, and a reserved
  independent index location.
- List/get/create/update database storage and API paths that do not require an
  active Series.
- Revision-protected link and unlink behavior validating real Series IDs.
- Source list/get/import/update scoped by Research Database ID, with duplicate
  detection and path validation limited to that database.
- Explicit legacy discovery and copy migration with exact read-back verification
  and unchanged version 1 rollback files.
- Research UI for empty library, database creation, switching, database
  properties, current-Series link state, source import/preview/properties, dirty
  draft protection, compact layout, and honest format limits.
- Focused contract, storage, route, Web, real browser, documentation, and full
  regression evidence.

## Out Of Scope

- DOCX, PDF, EPUB, HTML, URL fetching, OCR, browser capture, or automatic
  internet research; these follow in NS-604 after Source location/chunk rules.
- Keyword, semantic, translated, or multi-database search. The accepted
  selection boundary is recorded now, not presented as a working control.
- Research Database archive, permanent delete, merge, export, backup, or
  automatic sharing.
- Deleting legacy Series-owned Research files after migration.
- Changing the JSON authority of Series, manuscript, Codex, or Workshop data.
- Changing the Series-owned manuscript projection database topology.

## Logical Closure Boundary

| Boundary | NS-603 handling |
| --- | --- |
| Authoritative data | ResearchDatabase v1 and SourceDocument v2 JSON plus managed originals inside one library-level database root |
| Read paths | Database list/get, linked-Series state, scoped Source list/get, and explicit legacy discovery |
| Write paths | Revision-safe database create/update/link and scoped Source import/update; explicit verified legacy copy |
| Derived state | Independent reserved database index boundary only; search projections remain deferred |
| User entry points | Library-level Research workspace and `/api/v1/research/databases` routes |
| Lifecycle | Create, select, edit, link, unlink, and migrate; archive/delete remain absent |
| Migration/rollback | Version 1 Series Source remains unchanged; version 2 copy plus migration receipt is atomic and verifiable |
| Fixtures | Empty library, two databases, same hash across databases, cross-database authority substitution, two linked Series, stale revisions, injected failures, and legacy migration |
| Acceptance | Exact proofs in `docs/testing/NS-603_ACCEPTANCE.md`; author visual decision remains separate |

## Completion Criteria

- A01-A11 pass with actual evidence and A12 remains open until the author makes
  the separate visual decision.
- Existing NS-602 legacy bytes and `data/library/` are not modified by tests or
  implementation work in this checkout.
- Each database's authority and Sources remain readable when another database
  is missing, damaged, or rebuilding.
- Word, PDF, EPUB, HTML, URL, search, archive, delete, and merge do not appear as
  working controls before their real commands exist.

## Implementation Result

- ResearchDatabase version 1 and SourceDocument version 2 are implemented as
  library-scoped JSON authority under isolated database roots. Database and
  Source writes use the existing coordinated transaction and revision model.
- Library-scoped REST routes and the connected Research workspace create,
  select, edit, link, import, restore, and migrate without requiring an open
  Series. The retired Series Source route returns `404`.
- Explicit legacy migration preserves the version 1 Series files, copies exact
  originals with provenance into one linked target database, and writes a
  per-database receipt. Injected failure leaves no visible target Source.
- Real-Chrome and independent API/disk probes found and fixed two Web state
  races: initial mounting erased the remembered database, and database changes
  briefly combined the new database identifier with the previous Source
  identifier. Source shelves now carry their owning database state.
- Desktop inspection found and fixed an unnecessary empty-reader scrollbar.
  The compact toolbar keeps an explicit `Settings` label and passes 720-pixel
  width and overflow checks.
- A01-A11 are implemented and evidenced in implementation commit `d518666`.
  A12 remains the author's separate connected-page visual decision.
