# NS-407：流式 AI 调用、调用日志与正文内联候选

状态：完成  
里程碑：M4

## 目标

建立 M4 第一条真实 AI 调用闭环：

1. 基于已保存的 `ContextBundle`、`PromptTemplate` 和 `ModelProfile` 发起模型调用。
2. 使用 SSE 返回流式文本。
3. 保存可审计 `ModelCallLog`。
4. 写作页可以发起“审稿”和“改写”两类最小调用。
5. AI 不能绕过作者确认修改正文、设定、摘要、故事进展或角色所知。

## 已实现

- 新增 `CreateModelCallInput` 与 `ModelCallStreamEvent` 契约。
- 新增 `apps/server/src/routes/modelCalls.ts`：
  - `POST /api/v1/series/:seriesId/ai/calls`
  - `GET /api/v1/series/:seriesId/ai/calls`
  - `GET /api/v1/series/:seriesId/ai/calls/:modelCallId`
  - `GET /api/v1/series/:seriesId/ai/calls/:modelCallId/context`
- 调用流程：
  1. 读取并校验 `ContextBundle`、`ModelProfile` 和调用边界。
  2. 检查云端权限和凭据引用边界。
  3. 估算上下文与提示词 token。
  4. 创建 `pending` 调用日志。
  5. 使用 ProviderAdapter 流式生成文本。
  6. 写入 `succeeded` 或 `failed` 日志，记录请求 / 响应哈希、状态、错误和用量。
- MockProvider 在分析任务中返回非写入分析结果，在 `rewrite` 等正文任务中返回候选正文。
- 前端 `api.streamModelCall` 支持解析 SSE。
- 写作页右侧新增 AI 面板：
  - “审稿”：结果显示在侧栏，不写入正文。
  - “改写”：对当前正文选区生成候选。
- 正文候选确认规则：
  - AI 输出直接放入正文编辑器，不开单独窗口。
  - 候选放入后整段选中。
  - 自动保存暂停，状态显示“候选待确认”。
  - 点击“保留”后才进入普通保存流程。
  - 点击“撤回”恢复生成前正文。
- 调用记录保存于后端和 API；写作主界面不显示调用来源、基准版本、用量或调用 ID，完整日志界面留给 `NS-409`。

## 明确未实现

- 真实 Provider 仍属 `NS-408`。
- 完整调用记录 / 上下文快照浏览 UI 仍属 `NS-409`。当前可通过 API 读取调用日志和实际上下文快照。
- 摘要、人物状态、设定、故事进展、角色所知等事实候选收件箱仍属 M5。
- 多编辑会审仍属 M5。

## 设计备注

用户界面应从作者视角出发。安全边界、调用 ID、提示词版本和上下文快照必须可审计，但不应成为写作页主视觉。写作页只呈现“审稿 / 改写”“要求”“结果”“候选待确认 / 保留 / 撤回”。调用来源、基准版本、用量和调用 ID 只属于调用记录，不得出现在正文候选确认条。
