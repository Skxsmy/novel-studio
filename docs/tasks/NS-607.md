# NS-607 Workshop Research Database Integration And Behavior Harness

Status: paused
Milestone: M6.6
Predecessor: NS-606
Governing decisions: `docs/adr/0021-tool-driven-research-retrieval.md`,
`docs/adr/0023-workshop-research-activation-and-tool-loop.md`

Canonical author-facing hierarchy: `Series → Volume → Chapter → Act → Scene`.

## Goal

Let an author activate several library-scoped Research Databases for one
Workshop session and let General Chat or Agent actively retrieve bounded
evidence through native Provider tool calls until the current author question
is resolved. Unify every current Workshop tool behind a production behavior
harness that constrains model-visible capabilities, validates tool use, protects
author-confirmed writes, and can be evaluated across realistic multi-turn author
workflows.

## In Scope

- Versioned session-level activation authority, explicit migration to an empty
  selection, rollback tests, branch inheritance, archive/read-only behavior,
  permanent-delete cleanup, and damaged-record diagnostics.
- A compact Workshop database selector near the composer. Linked databases are
  promoted for discovery but all library databases remain selectable; selecting
  one never changes Series links or ownership.
- Context preview showing active database metadata and tool availability, not
  prefetched Source bodies.
- Bounded native-tool continuation loops for General Chat and Agent, with the
  same operation cancellation, session activity boundary, streaming identity,
  retry/audit, and context-window protection as existing model calls.
- Immediate execution of read-only Research tools and unchanged confirmation
  behavior for Codex or future write tools.
- User-visible citations that open the exact Research passage and disclose the
  database and retrieval channels.
- Clear unavailable/degraded state for models without native tool calls or for
  missing validated cross-language profiles.
- One server-owned Workshop tool policy covering `research.list_sources`,
  `research.search`, `research.open_passage`, `codex.create_entry`, and
  `codex.update_entry`, including mode visibility, side-effect class,
  confirmation policy, validation timing, and terminal behavior.
- Production pre-execution and post-execution guardrails that enforce the policy
  independently of model prose, with model-visible bounded correction where it
  is safe.
- A reusable behavior-evaluation harness with task, trial, trace, outcome,
  trajectory, and dialogue graders. It must support real Provider adapters in
  NS-608 without replacing them with scripted answers.
- Multi-session, multi-turn author scenarios for ordinary discussion, durable
  short corrections, Codex create/update, Research-only work, Research followed
  by a separately confirmed Codex write, negative tool-triggering cases,
  cancellation, stale confirmation, and replay protection.

## Frozen Implementation Decisions

1. `WorkshopSession` advances to schema version 3 with an ordered, unique
   `activeResearchDatabaseIds` array containing zero to twelve UUIDs. New and
   migrated sessions start empty. The repository never infers activation from a
   Series link.
2. The storage layer owns an explicit all-or-nothing version 1/version 2 to
   version 3 migration with exact raw backups and revision-checked rollback.
   Valid sessions may be listed alongside path-confined diagnostics for damaged
   records; damage is not silently dropped or rewritten.
3. Branching copies the settled source prefix and its activation snapshot.
   Archived sessions expose activation read-only. Session deletion removes the
   activation with the session; database deletion is blocked while an archived
   or active Workshop session still names it and reports the affected sessions.
4. One author turn owns one bounded server coordinator. It alternates Provider
   native tool calls, automatic read-only Research execution, and Provider
   continuation without recursive HTTP routing. Agent write tools remain
   pending author-confirmed protocol messages and may not be mixed with an
   automatic read tool in the same Provider step.
5. Research evidence used by a completed assistant answer is persisted as a
   versioned message-evidence record. The record contains immutable citation
   anchors and display metadata, not copied Source bodies. Clicking a citation
   opens the Research workspace at the exact database, Source, revision, and
   Chunk location.
6. Active database metadata is transmitted through dynamically described native
   tool definitions and is presented in the Workshop source control. It is not
   appended to the editable General Chat system prompt, and no Source body is
   prefetched into the initial request.
7. The author explicitly rejected Figma for this surface. NS-607 uses the local
   `ui-design` skill, existing Novel Studio tokens/components, and the direct-code
   structure checklist below. Automated checks may verify layout behavior but
   cannot claim author visual acceptance.
8. The Workshop behavior harness covers all currently exposed Workshop tools;
   Research is not treated as a separate agent architecture. Production
   constraints, deterministic protocol regressions, and stochastic model
   behavior evaluations are distinct layers and may not substitute for one
   another.
9. A short author correction persists for later turns in the same session and
   must constrain ordinary prose, searches, and Codex drafts. Evaluation prompts
   use natural author language rather than requiring the author to describe
   schemas, tool names, or prompt-engineering techniques.

Novel Studio adopts source selection, exact evidence navigation, bounded visible
activity, and explicit loop stopping. It does not adopt a new runtime dependency,
an opaque hosted agent, or a verbose trace dashboard.

The deterministic scripted Provider remains the protocol-regression layer. It
uses expected step matchers, native tool emissions, usage records, abort
barriers, injected errors, and transcript assertions against real
HTTP/storage/gateway paths. It does not measure whether an unconstrained model
chose the right tool or respected an author correction.

The production behavior layer owns the tool policy, active tool set,
pre-execution validation, confirmation boundary, post-execution validation,
loop budgets, and replay prevention. The behavior-evaluation layer runs
realistic tasks through that production layer, records complete traces, checks
authority outcomes and allowed/required/forbidden trajectory constraints, and
scores interaction quality. NS-607 proves the framework and deterministic
reference cases; saved-key, multi-trial model evidence remains NS-608.

## Out Of Scope

- Automatic database activation from a Series link.
- Hidden prompt injection or mechanical prefetch of all matching passages.
- Any model-initiated Research mutation.
- Claiming real-world author acceptance from Mock Provider tests.
- Treating deterministic scripted Provider output as evidence that a real model
  reliably follows the behavior contract.

## Required Closure

1. Several read calls may occur in one author turn, but server budgets and
   no-progress limits always terminate the loop.
2. Switching sessions preserves each session's own active databases and
   in-flight retrieval state; branching copies only the settled source prefix
   and the activation snapshot defined by the migration contract.
3. General Chat's visible editable system prompt remains unchanged and complete;
   tool definitions and traces are separately visible in audit.
4. Every displayed citation opens a passage from an active database and matches
   the persisted Source revision/hash/location.
5. The task receives its own acceptance record and exact test mapping before
   runtime edits begin.
