# NS-405：场景级上下文装配器

状态：完成。

## 目标

按当前场景生成可审计的 `ContextBundle`，让作者和后续调用日志都能看到 AI 将获得哪些资料、哪些资料被排除，以及排除原因。

## 已交付

- 新增上下文预览 API：
  - `POST /api/v1/series/:seriesId/context/preview`
  - `GET /api/v1/series/:seriesId/context/:contextBundleId`
- 新增 `ContextPreviewInput` 契约，包含：
  - 当前场景 ID。
  - 编辑角色 ID。
  - 任务类型。
  - 用户请求。
  - 提示词模板 ID 与版本。
  - 正文选区。
  - 主动选择资料 ID。
  - 可选模型配置 ID。
  - 可选 token 预算。
- 预览包会纳入：
  - 编辑职责占位。
  - 用户当前请求。
  - 当前场景标题、目标、冲突、结果、摘要、节拍和正文。
  - 唯一可定位的正文选区。
  - 前一个场景摘要。
  - 当前场景可读取的设定条目。
  - 截至当前叙事位置有效的世界事实、关系变化和角色所知。
  - 作者主动选择且权限允许的附属文档。
- 预览包会记录排除项：
  - 后一个场景和后文信息。
  - `never` 资料，即使主动选择也排除。
  - 隐藏区段。
  - 云端模型下的仅本机资料。
  - 未主动选择的 manual 资料。
  - 超出 token 预算后被裁剪的资料。
- 生成的 `ContextBundle` 会保存到 `.studio/context-bundles`，可通过 ID 复查。
- 写作页右侧“场景资料”加入最小上下文预览入口：
  - 可选择参考模型或不指定模型。
  - 可生成预览包。
  - 显示纳入项、排除项和用量估算。

## 不变量

- 上下文预览不调用模型。
- 上下文预览不修改正文、已确认设定、摘要、故事进展或角色所知。
- 未来剧情只记录“被排除”和数量，不把未来摘要、证据或内部 ID 向前泄露。
- 每个纳入项都带来源 ID、人类可读原因和估算用量。
- 每个排除项都带来源、人类可读原因和排除说明。
