# NS-602 Database Kernel And Research Source Vertical Slice

Status: complete
Created: 2026-07-19
Owner: Codex
Acceptance: `docs/testing/NS-602_ACCEPTANCE.md`

## Objective

Deliver the first usable Reference Library workflow for an author: open the
independent `Research` workspace, import a real TXT or Markdown source, retain
the unchanged original and schema-versioned JSON authority, inspect parse
status and original text, and revise author-owned source properties without
losing concurrent edits. At the same time, replace the unversioned live-clear
SQLite index path with the first versioned, validated, atomically replaceable
database kernel while preserving existing Scene, Codex, mention, and AI index
behavior.

Canonical author-facing hierarchy remains `Series → Volume → Chapter → Act → Scene`.
The compatibility mapping remains `Series → series`, `Volume → book`,
`Chapter → act`, `Act → chapter`, and `Scene → scene`; Research does not expose
those internal storage names.

## Recorded User Decision

The author rejected the old Figma path on 2026-07-19 because the Research design
there is obsolete. The Research workspace is designed directly in the existing
React application with the installed `ui-design` Skill, current shared tokens,
current author workflows, and the named written checklist
`docs/design/ui-redesign/NS-602_RESEARCH_UI_CHECKLIST.md`. The old disabled
Research placeholder and any old Figma frame are not binding for this page.
This decision does not waive the separate author visual-acceptance gate and does
not silently change already accepted structures on unrelated workspaces.

  Studio shell and operational author workflow are the relevant design context.

## In Scope

- SourceDocument version 1 contracts for TXT and Markdown source authority,
  parse status, immutable import facts, author-editable properties, AI context
  permission, and revision-bearing API responses.
- A bounded JSON upload contract with exact byte count, SHA-256, strict UTF-8
  decoding, extension/media-type agreement, empty/oversize rejection, duplicate
  hash rejection, and filename/path containment.
- One coordinated Series file transaction that writes the unchanged original
  text and SourceDocument JSON authority together.
- List, get, create/import, and revision-safe property update repository and API
  paths. Delete, archive, reparse, batch edit, search, and AI ingestion are not
  exposed in this slice.
- A versioned SQLite kernel boundary with fixed connection policy, migration
  identity, schema checksum, health checks, serialized per-Series rebuild, a
  temporary build directory, validation, and atomic live-index replacement.
- Preservation of current Scene, Codex, mention, ambiguity, Context Bundle, and
  Model Call projection behavior behind that boundary.
- An enabled `Research` workspace in the main shell, with real empty, loading,
  uploading, selected, saving, and failure states.
- Desktop and compact layouts that preserve a source list, readable original
  preview, and property editor without nested card stacks or fake commands.

## Out Of Scope

- DOCX, PDF, EPUB, HTML, OCR, browser capture, or remote research acquisition.
- Keyword search, semantic search, query translation, transliteration,
  embeddings, cross-language result fusion, and Research Notes.
- Source deletion, archive, reparse, version linking, batch property edits, or
  Canon conversion.
- Library-wide `catalog.sqlite`, vector storage, final multilingual model
  selection, or a new text-analysis dependency.
- Any modification to the user's existing `data/library/` authority or derived
  databases during automated tests.

## Logical Closure Boundary

| Boundary | NS-602 obligation |
| --- | --- |
| Authority | SourceDocument JSON plus unchanged managed original are the only source truth; SQLite remains disposable |
| Read paths | List and get validate authority and return revision, parse state, immutable facts, editable properties, and preview text |
| Write paths | Import and property update use repository-owned validation, revision checks, durable transaction, and read-back verification |
| Derived state | Versioned `.studio/index.sqlite` kernel, schema registry, health report, and atomically replaceable rebuild output |
| User entry | Independent main-nav `Research` workspace with upload, source selection, preview, and property save |
| Lifecycle | Created/parsed and failed request states only; unsupported lifecycle commands remain absent |
| Recovery | Interrupted source transaction recovers; failed/cancelled index build leaves live index readable; legacy v0 rebuilds from authority |
| Security | No path escape, no active content execution, no credential/manuscript logging, bounded payload and decoded text |
| Acceptance | Exact proofs in `docs/testing/NS-602_ACCEPTANCE.md`; author visual acceptance remains separate |
