# NS-605 Multi-database Hybrid And Cross-language Retrieval

Status: in_progress
Milestone: M6.4
Predecessor: NS-604 automatic gates A01-A13; its independent A14 author visual gate remains open by explicit user direction
Governing decisions: `docs/adr/0021-tool-driven-research-retrieval.md`; `docs/adr/0022-isolated-research-vector-index.md`

Canonical author-facing hierarchy: `Series → Volume → Chapter → Act → Scene`.

## Goal

Build a retrieval service that explicitly queries one or several isolated
Research Databases and can retrieve relevant Chinese, Japanese, and English
original passages even when the query and passage share no terms. This task
ends at a tested retrieval service and author-facing Research search; it does
not connect a model or Workshop.

## In Scope

- Explicit selected-database query input and labeled deterministic result
  fusion without merging database authority, files, indexes, or permissions.
- Existing literal, CJK trigram, and Unicode word channels with normalized
  channel-specific scores.
- Author-confirmed alias and transliteration channel with provenance.
- Versioned multilingual embedding profile binding, capability fixture, vector
  provenance, incremental rebuild, cancellation, and exact-only degradation.
- Optional versioned query translation only after Provider, privacy, and
  language-pair permission checks.
- Reciprocal-rank or equivalent deterministic fusion, deduplication, source
  diversity, relevance threshold, pagination, and channel disclosure.
- Chinese-to-Japanese, Chinese-to-English, reverse-language, mixed-language,
  proper-name, false-friend, and irrelevant-negative fixtures.

## Approved Implementation Decisions

1. Multi-database search receives one to twelve explicit unique Research
   Database IDs. The current database remains the default single selection;
   opening a Series does not silently add linked databases.
2. Each database owns a versioned `retrieval/aliases.json` authority document.
   Entries contain an author-entered query term, an expansion term, whether the
   relationship is an alias or transliteration, language tags, and an optional
   note. Missing files mean an empty set. Writes are revision-checked and
   atomic; aliases never become Source text or Evidence.
3. No library-wide catalog is introduced. The repository opens only the
   explicitly selected bounded database set and merges labeled responses in
   memory without attaching SQLite files or merging authority.
4. Vectors use the existing library-global Embedding profile and the stable
   `research.multilingual` use-case binding. A separate versioned capability
   record binds declared language coverage, query/document prefixes, and a
   fixture result to the exact profile revision. Only a passing capability
   record enables the semantic channel.
5. Every database owns an independent rebuildable vector sidecar. The sidecar
   uses exactly pinned `sqlite-vec` 0.1.9, loaded only from the reviewed package
   path on a dedicated vector connection. Arbitrary extension paths and SQL
   attachment remain unavailable. The dependency is dual MIT/Apache-2.0 and is
   pre-v1, so schema/application identity and the exact package version are
   pinned and deletion/rebuild behavior is tested.
6. Hybrid ranking uses deterministic weighted reciprocal-rank fusion across
   literal/CJK/word, alias, transliteration, optional query translation, and
   semantic channels. Results are deduplicated by database and Chunk, apply a
   minimum relevance rule, enforce source diversity, and use a query/snapshot-
   bound opaque cursor for pagination.
7. Query translation is optional and has no default Provider. It executes only
   through an explicit versioned binding after query-only privacy and language-
   pair checks; failure leaves disclosed lexical/alias/semantic results and
   never triggers another Provider.

## Author-facing Design Checklist

- Route: the existing `Research` workspace; no landing page and no Figma.
- Entry and return: the current Research Database remains selected. A compact
  scope control beside search opens a checkbox menu for one to twelve databases;
  result activation returns to the owning database, Source, Block page, and
  exact original-language passage.
- Layout: retain the continuous source shelf, reader, and properties layout.
  Search results become a dense evidence ledger with a database ribbon,
  original location/language, disclosed match channels, and score explanation.
- Controls: use a checkbox menu for database scope, a two-option segmented
  control for `Hybrid` and `Exact`, icon buttons for clear/settings, and real
  commands for alias management, capability validation, and vector rebuild.
- States: exact-only degradation, validating, indexing, partially unavailable
  sibling database, no results, stale cursor, cancelled rebuild, permission-
  excluded semantic sources, and retryable failures all have truthful text and
  enabled recovery actions.
- Data: every displayed count/status/result comes from the retrieval API and
  exact database/index state. No static semantic badges or fake percentages.
- Responsive: desktop keeps three columns; narrow layouts use the existing
  source drawer and place scope/mode controls on stable rows without horizontal
  overflow or nested cards.
- Design direction: a quiet editorial research console using the existing paper,
  ink, green, and restrained amber system. The signature element is the result
  ledger's database-and-channel ribbon, which makes provenance scannable without
  exposing engineering IDs. No targeted external component inspiration is
  needed for this incremental Research surface.

## Out Of Scope

- Provider tool definitions or model tool loops.
- Workshop session activation or UI.
- Research Source writes initiated by a model.
- Treating an embedding score or translation as Evidence.

## Required Closure

1. Every hit identifies its database, Source, Chunk, original hash/revision,
   language, location, and actual match channels.
2. An unvalidated or unavailable multilingual profile degrades to disclosed
   lexical/alias channels without silent Provider fallback.
3. Multi-database results are deterministic and never cross inactive database
   or `model-context` permission boundaries.
4. A damaged or rebuilding database does not corrupt or relabel a healthy
   sibling result set.
5. The task receives its own acceptance record and exact test mapping before
   runtime edits begin.
