# NS-606 Artificial-intelligence Research Retrieval Gateway

Status: in_progress
Milestone: M6.5
Predecessor: NS-605
Governing decision: `docs/adr/0021-tool-driven-research-retrieval.md`

Canonical author-facing hierarchy: `Series → Volume → Chapter → Act → Scene`.

## Goal

Expose the retrieval service as a server-owned, read-only, auditable tool
gateway for models. This task proves policy and tool execution independently of
Workshop presentation and conversation lifecycle.

## In Scope

- Strict Provider tool contracts for `research.list_sources`,
  `research.search`, and `research.open_passage`.
- A server-owned execution context containing active database IDs, Source
  permission purpose, model-call identity, cancellation signal, and fixed
  budgets.
- Database allowlist enforcement, argument validation, query and result size
  limits, relevance thresholds, deduplication, source diversity, per-call and
  cumulative character/token budgets, call-count limit, and no-progress limit.
- Results that contain bounded original passages plus complete citation anchors
  and disclosed retrieval channels.
- Durable redacted tool audit linked to the model call without logging keys,
  complete private Sources, request headers, or unmanaged file paths.
- Mock Provider and direct gateway tests for iterative search/open behavior,
  invalid calls, inactive databases, `never` Sources, cancellation, restart,
  and attempted whole-database extraction.

## Approved Implementation Decisions

1. The Provider-facing names are exactly `research.list_sources`,
   `research.search`, and `research.open_passage`. Their strict JSON schemas do
   not expose imports, writes, index operations, file paths, credentials, or
   server budget fields. A native-tool-capable model receives all three; a
   model without native tool calls receives none.
2. `research.list_sources` names one active database and returns at most twelve
   permitted Source metadata rows. It never returns Source body text or managed
   paths. Its opaque cursor is bound to the active database and current Source
   revisions.
3. `research.search` searches all active databases unless its optional database
   subset is entirely inside the server allowlist. It may choose `Exact` or
   `Hybrid` and use the existing bounded filters, but cannot choose result count
   or relevance thresholds. One call returns at most six fused passages.
4. `research.open_passage` must provide the database, Source, Chunk, Source
   revision, and Chunk hash from a prior citation. The gateway verifies every
   field against current authority and returns the target Chunk plus at most one
   adjacent Chunk on each side. A stale or forged citation returns a bounded
   tool error rather than another Source.
5. One gateway execution context is bound to one Series, one existing model
   call, one to twelve active Research Database IDs, `model-context` permission,
   and an optional cancellation signal. Default immutable limits are eight tool
   calls, two consecutive no-progress calls, 16,000 output characters and 8,000
   estimated tokens per call, and 48,000 characters and 24,000 estimated tokens
   cumulatively. Search/list/open page sizes are additional hard limits.
6. Progress means returning a Source or citation identity not returned earlier
   in the same model call. Repeated argument hashes and duplicate-only result
   sets consume the call budget. The second consecutive no-progress result marks
   the gateway exhausted; later calls are rejected without reading another
   database.
7. Tool output token estimates use the repository's existing deterministic
   `ceil(Unicode code points / 2)` estimate. The independent hard character
   limits remain authoritative even when a Provider tokenizer differs.
8. Durable audit is stored under the owning Series at
   `.studio/research-tool-audits/<model-call-id>/`. Each atomic schema-versioned
   event stores sequence, tool/status, argument hash and bounded structural
   summary, citation anchors without passage text, output counts, budget state,
   and generic error code. It never stores query text, full Source text, API
   keys, headers, Provider bodies, or managed/unmanaged file paths.
9. Gateway construction replays the existing audit sequence to restore call,
   output, progress, and exhaustion state after restart. A damaged, non-
   contiguous, cross-Series, or cross-model-call audit sequence fails closed.

## Out Of Scope

- Workshop activation controls and conversation rendering.
- General Chat or Agent run-coordinator changes.
- Any Research write/import/property/lifecycle tool.

## Required Closure

1. A model cannot widen the active database set or any server budget through
   tool arguments.
2. Read calls execute without write confirmation and cannot mutate Source,
   index, Series, Codex, or Workshop authority.
3. All returned text is attributable to exact original-language citation
   anchors; summaries and model prose are not relabeled as Source text.
4. Models without native tool calls receive no executable Research tools.
5. The task receives its own acceptance record and exact test mapping before
   runtime edits begin.

## Implemented Runtime Boundary

- `packages/contracts/src/researchTools.ts` defines the three strict argument
  schemas, bounded model-visible results, immutable citation identity, exact
  budget state, generic errors, and text-free audit events.
- `packages/storage/src/researchToolAudits.ts` atomically appends one contiguous
  audit event per call under the owning Series and rejects missing Model Call
  Logs, stale sequences, path escape, unexpected entries, cross-identity files,
  malformed JSON, and non-contiguous restart state.
- `apps/server/src/researchToolGateway.ts` gates definitions on Provider native
  tool support and binds execution to one active Model Call Log, one active
  database allowlist, the `model-context` permission purpose, fixed limits, and
  an optional cancellation signal. It serializes concurrent calls for the same
  model call and restores progress from durable audit.
- `research.list_sources` reads Source metadata only; body counts remain `null`
  instead of loading large Source content. `research.search` reuses NS-605
  threshold, deduplication, diversity, original-language evidence, and isolated
  Hybrid behavior. `research.open_passage` requires a prior exact citation and
  rechecks current permission, Source revision, Chunk identity, and hash.
- The gateway performs no Research, Series, Codex, Workshop, index, or file
  mutation. Its sole write is the redacted audit event. Unsupported Providers
  receive no Research definitions. Completed model calls cannot create a new
  gateway.

## Dependency Review

NS-606 adds no dependency. It reuses Zod, the current Provider native-tool
types, ProjectRepository transactions, the NS-605 retrieval service, and the
existing deterministic token estimate.
