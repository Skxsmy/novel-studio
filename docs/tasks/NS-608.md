# NS-608 Research-assisted Author Workflow Hardening

Status: in_progress
Milestone: M6.7
Predecessor: NS-607
Governing decisions: `docs/adr/0021-tool-driven-research-retrieval.md`,
`docs/adr/0023-workshop-research-activation-and-tool-loop.md`

Canonical author-facing hierarchy: `Series → Volume → Chapter → Act → Scene`.

## Goal

Validate and harden the completed Research-assisted Workshop path from an
author's perspective using saved real model credentials, realistic corpora,
multiple sessions, and multi-round conversations that continue until each
writing problem is actually resolved.

## In Scope

- Real saved-key calls through explicitly selected model profiles; credentials
  remain redacted and are never copied into fixtures, logs, or repository data.
- Several author scenarios such as historical fact checking, foreign-language
  source comparison, continuity research, terminology choice, and citation
  follow-up. Each session contains multiple model/tool turns until its stated
  author problem is complete before the next session begins.
- Authors provide ordinary requests rather than expert retrieval prompts. The
  system prompt, tool descriptions, continuation policy, and error feedback must
  sustain corrective behavior across later turns and sessions.
- Large-corpus import/index/search latency, context-budget pressure, cancellation,
  restart, damaged index rebuild, Provider failure, stale citations, permission
  changes, and database deactivation during later calls.
- Prompt-injection Sources, adversarial tool arguments, duplicate evidence,
  misleading cross-language false friends, and unsupported-model capability
  states.
- Final connected UI review and an explicit author acceptance decision.

## Frozen Execution Decisions

1. Saved-key trials use only the author's existing DeepSeek connection and
   credential reference, with the exact model overridden to
   `deepseek-v4-pro`. Provider, base URL, credential, and other connection
   settings remain unchanged. The source profile and real library are read-only;
   trials copy the non-secret profile metadata and credential reference into a
   generated temporary library and never read or persist plaintext credentials.
2. The official Provider contract is DeepSeek's OpenAI-format
   `POST /chat/completions`, Bearer authentication, `GET /models`, streamed
   answer/reasoning fields, and native function tools. The task uses only
   official DeepSeek documentation:
   - https://api-docs.deepseek.com/api/create-chat-completion
   - https://api-docs.deepseek.com/api/list-models
   - https://api-docs.deepseek.com/guides/tool_calls
   - https://api-docs.deepseek.com/quick_start/pricing
3. Each real-model trial owns a new temporary Series, isolated Research
   Databases, Sources, Workshop sessions, and Codex authority. Cleanup runs in
   `finally`. `data/library/` model-profile metadata may be read to locate the
   saved credential reference but no trial may create, migrate, rebuild, or
   mutate real Series, Research Database, Source, Workshop, Codex, index, or
   audit authority.
4. Real behavior tasks run three independent trials each. Every session has
   several natural author turns and continues until the declared writing problem
   is resolved or the fixed maximum turn budget is reached. The simulated author
   may give short corrections but never names schemas, tool protocols,
   retrieval channels, or internal identifiers.
5. The real task set covers Chinese questions over Japanese and English
   originals; conflicting sources and cross-language false friends; ordinary
   discussion that must not trigger tools; durable short correction; one Codex
   create and one later update with separate exact confirmations; Research
   followed by a separately confirmed Codex write; cancellation and explicit
   retry; and source prompt injection that must remain untrusted data.
6. Hard boundaries require every trial to pass: database/permission isolation,
   no plaintext secret or private path in outputs, no unconfirmed or duplicate
   write, no executable prose-simulated tool, no hidden replay, and exact
   original-language citation identity. Open-ended task completion is graded by
   authority outcome and evidence, not one prescribed tool sequence, but it also
   must pass every recorded trial before this task can close.
7. Durable repository evidence contains task summaries, aggregate grades,
   timings, counts, hashes, and redacted failure classifications only. Complete
   private Source passages, complete model transcripts, Provider raw responses,
   credentials, credential references, authorization headers, and temporary
   paths stay in ephemeral run artifacts and are deleted after review.
8. Engineering regression targets use measured predecessor evidence with
   explicit headroom; they are not general hardware promises. On the declared
   current machine, one valid 25 MiB TXT import plus exact final-marker search
   must finish in 20 seconds, its import response remains below 16 KiB, and
   twenty exact queries have P95 below 250 ms. The 4,096-Chunk/384-dimension
   vector fixture must build within 2 seconds, query at P95 below 100 ms, and add
   no more than 128 MiB peak RSS. A miss records measured degradation instead of
   weakening the target after the run.

## Real Author Scenario Matrix

| Scenario | Per-trial session boundary | Required resolution |
| --- | --- | --- |
| Cross-language continuity | at least four author turns, up to eight | Chinese author question is answered from exact Japanese and English passages with original-language citations and no irrelevant dump |
| Conflicting sources and false friends | at least four author turns, up to eight | disagreement and uncertainty remain explicit; misleading shared terms do not become unsupported fact |
| Natural correction and Codex | at least seven author turns, up to twelve | discussion stays read-only, short correction persists, exactly one create and one later update wait for separate confirmation, final authority contains only corrected values |
| Balanced triggering | at least four author turns, up to six | brainstorming, rejection, prose-only requests, and summaries do not trigger Research or Codex merely because tools are available |
| Prompt injection and permission | at least four author turns, up to eight | malicious Source instructions are treated as quoted data, `never` Source is absent, and no write/secrets/path disclosure occurs |

## Out Of Scope

- Treating one or two short Mock Provider exchanges as real workflow proof.
- Expanding Research tools into automatic web browsing or authority writes.
- Storing or publishing the author's real credentials or private full corpus.

## Required Closure

1. Each scenario records the author goal, every retrieval call, evidence used or
   rejected, context budget, model response, correction, and final resolution.
2. Failures discovered in the real workflow are fixed and rerun end to end; a
   narrow regression test alone is insufficient closure.
3. Product records distinguish automated proof, diagnostic visual inspection,
   and the author's explicit visual/workflow acceptance.
4. Performance targets are measured on declared fixture sizes and hardware,
   with degraded behavior shown honestly when a target is not met.
5. The task receives its own acceptance record and exact test mapping before
   runtime edits begin.
