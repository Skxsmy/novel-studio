Status: complete

## Objective

Replace exact-name-only Workshop Codex detail resolution with a category-scoped schema planner that recommends reusable detail types before creation, persists the embedding use-case binding, and requires an explicit author mapping or fully specified creation choice before the existing atomic Codex command executes.

## In Scope

- Persist library-global `EmbeddingUseCaseBinding` records for use cases including `codex.detail-schema`, with profile-reference validation and restart-safe reads.
- Expose storage and REST boundaries for reading, setting, and deleting use-case bindings without mixing them into generation model profiles.
- Add a server-owned detail schema planner that keeps stable-ID and exact normalized name matches deterministic, embeds only unmatched labels and same-category reusable detail type names, scores cosine similarity, and returns ranked suggestions with author-readable reasons.
- Return explicit planner states for ready, unconfigured, and unavailable embedding paths. No failure path may silently select another profile, contact another Provider, create a detail type, or treat similarity as Evidence.
- Extend the Workshop tool-resolution response with planner suggestions while retaining the complete same-category detail type list for manual mapping.
- Replace implicit create-all behavior with one explicit choice per unmatched label: map to an existing detail type or create a type with an author-confirmed final name and NSFW flag.
- Include mapping/creation choices in the existing tool confirmation identity and execute them through the NS-507 atomic repository command.
- Add focused contracts, storage, server/planner, route, and web tests plus proportionate regression checks.

## Out Of Scope

- Embedding profile creation/editing UI, model download, or automatic local service startup.
- Persistent vector indexes or cached detail vectors; NS-508 may compute request-local vectors because detail-type sets are small and vectors are derived state.
- Cloud fallback, automatic network research, or use of semantic similarity as Canon, Evidence, or write authorization.
- Generation-model Prompt changes, durable multi-step Agent runs, Tool Plan/Grant, broader Codex tools, or Proposal fallback completion.
- Renaming existing detail types or changing their category.
- User visual acceptance for the full Workshop page.

## Logical Closure Boundary

| Boundary | Handling |
| --- | --- |
| Authoritative data | Library-global embedding profiles and new use-case binding JSON; Series detail types remain Codex authority |
| Read paths | Binding repository/API, planner profile resolution, same-category detail type reads, Workshop resolution response |
| Write paths | Binding set/delete commands; author-confirmed detail mapping/creation enters the existing NS-507 atomic Codex command |
| Derived state | Request-local embedding vectors and scores only; no vector cache becomes authority |
| User entry points | Embedding binding REST boundary and Workshop per-label mapping/create confirmation panel |
| Lifecycle | Deleted binding disables semantic planning; archived/missing profile produces an unavailable planner state; detail type lifecycle remains unchanged |
| Migration/rollback | No authority-schema migration of existing files; removing binding files returns planner to unconfigured manual mode; no vectors require rollback |
| Fixtures | Restart reload, missing/archived/wrong profile, semantic near/far candidates, duplicate choices, omitted choices, NSFW creation, and provider failure |
| Acceptance | `docs/testing/NS-508_ACCEPTANCE.md` |

## Decisions And Open Questions

- Stable detail type ID and unique exact normalized name remain deterministic matches and do not need embedding.
- Semantic candidates are restricted to the entry category. The planner ranks suggestions but never treats similarity as evidence or authority.
- A strong candidate may be preselected in the author mapping panel, but the existing final tool confirmation remains required and the author can replace that choice.
- Creation is never the result of planner failure. The author must explicitly choose creation and confirm both the final reusable name and NSFW flag.
- An absent binding or failed embedding call degrades to manual mapping/create choices with an author-readable state; it does not block the tool indefinitely and does not silently choose another profile.
- No new dependency is required. Cosine scoring uses existing runtime code and the existing `@novel-studio/ai` embedding router.
- No ADR is required because the task implements the already accepted library-global profile/use-case routing and reusable-detail-type boundaries without changing authority ownership.
